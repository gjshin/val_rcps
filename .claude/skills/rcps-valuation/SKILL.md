# 계약서 → 입력 검토 → OK → 조서 묶음

이용자는 코드를 모른다. 설명은 이용자 관점의 쉬운 한국어로, 코드 이야기는 하지 않는다.
**칸마다 묻지 않는다.** 판단이 필요한 자리는 추천안을 채우고 근거·대안의 영향을 적어 한 번에 확인받는다.

## 1. 받을 자료 (처음에 한 번에 요청)

| 자료 | 쓰는 곳 |
|---|---|
| 계약서 일체 — 신주인수계약·별첨(발행조건)·주주간계약 | 계약조건 전부 |
| 평가기준일 KIS-Net 기준수익률 표(엑셀) | 무위험(국고채)·위험(등급별) 곡선 — **잔존기간을 덮는 만기까지** |
| 지분평가 결과(주당가치·보통주식수·전환 시 증가 주식수) | 주가 · 희석 확인 |
| **변동성 패키지(JSON)** — 이용자가 `streamlit run vol_app.py` 로 뽑아 준다 | σ 와 변동성 산출내역 시트. 이 작업 환경은 야후 주가 조회가 막혀 있다 |
| (있으면) 전기 보고서·전기 시나리오 | 전기 대비 변경점 |

빠진 자료가 있어도 멈추지 않는다 — 있는 것으로 입력표를 만들고 「받아야 할 것」에 적는다.

## 2. 입력 검토 문서 (한 번에 건넨다)

`docs/입력안내_RCPS.md` · `docs/입력안내_BW.md` 의 칸 순서를 따른다. 세 부분이다.

1. **입력표** — 칸 / 값 / 계약 근거(조항). 계약서 숫자는 그대로 적고 환산은 앱 칸이 한다
   (예: 배당률 액면 기준 1% → 「배당률 기준 = 액면가 기준」)
2. **제가 정한 가정** — 판단이 필요한 자리마다 추천안 · 이유 · 대안을 쓰면 값이 얼마나 움직이는지
3. **이슈사항** — 평가액을 크게 움직이는 것부터. 전기 대비 변경점, 회계 쟁점, 평가에서 뺀 권리

### 반드시 짚는 자리 (트러스테이 건에서 나온 것)

* **배당률 기준** — 「1주당 액면가액 기준 연 x%」 면 액면가 기준 (그대로 넣으면 발행가÷액면가 배 부풂)
* **이미 지급한 배당의 공제 방식** — 계약 문언(「지급된 배당금을 공제」 → 받은 금액만 공제)
* **존속기간 만료 시** — 보통주 자동전환인지 현금상환인지. 자동전환이면 상환청구권을 0 으로 두면
  구성요소 분해에서 전환권이 음수로 나온다(합계는 맞다 — 보통주 가치만 남는다)
* **배당가능이익 제약** — 상환이 「소멸」이 아니라 「이연」이면 상환청구 시작을 배당가능이익 회복
  예상 시점(사업계획상 결손금 해소 → 다음 정기주총 뒤)으로 늦추는 안을 기본으로, 계약대로 / 0 을 민감도로
* **리픽싱 조정 방식** — 앱 기본은 「하향 + 상향」이다. 회사 행위로만 일어나는 조정(저가발행·IPO·M&A)
  이면 「조정 없음」 — 켜 두면 첫 노드부터 전환가가 주가로 내려가 값이 두 배로 튄다
* **희석** — 지분평가 주당가치가 희석 전인지. 전환 시 증가 주식수 ÷ 보통주 > 10% 면 적는다
* **거래가격과의 차이** — 공정가치가 취득가(100)와 크게 다르면 그 이유(보호장치 가치·가정)를 적는다.
  제1113호 문단 64(보정) · 제1109호 B5.1.2A(최초 인식 차이)
* **회계기준·관점** — 발행자가 일반기업회계기준이면 RCPS 는 자본(회계기준원 GKQA09-024) → 발행자 평가
  불필요. 투자자 조서인지 발행자 조서인지
* **곡선 범위** — 곡선 마지막 만기가 잔존기간보다 짧으면 평탄 연장 경고가 뜬다
* **노드 간격** — 전기와 같게(주 단위면 수식 조서가 크고 느리다)
* **평가에 반영하지 않은 권리** — 조건부 매수청구권·잔여재산 우선분배·회사 행위 조정 등은
  `unmod_note` 에 한 줄씩

## 3. OK 를 받은 뒤 — 조서 묶음

**OK 전에는 조서를 만들지 않는다.** OK 를 받으면:

1. 입력표를 시나리오 JSON 으로 옮긴다 (앱 「시나리오 저장」과 같은 형식, `Terms` 칸 이름).
   **저장소 밖**(스크래치패드)에 둔다 — 고객 자료를 커밋하지 않는다
2. 민감도 목록 JSON — `[{"label": "…", "set": {칸: 값}}]` (행사 시점은 `p_s_date` 처럼 날짜로)
3. 실행:

   ```
   python3 tools/run_valuation.py 시나리오.json --out 출력폴더 --vol 변동성패키지.json --sens 민감도.json
   ```

   값 조서 · 수식 조서 · 시나리오 · 결과요약(md)이 나온다. 결과요약 끝의 **검사**(손상 검사 ·
   수식 조서 자체 검산)가 모두 통과인지 본다. 하나라도 불일치면 건네지 않고 원인을 찾는다
4. 이슈·민감도 메모를 결과요약에 덧붙여, 파일을 SendUserFile 로 건넨다. 한 줄 요약 —
   공정가치(100 기준·원화), 적용한 가정, 이슈 상위 셋

## 4. 하지 말 것

* 몬테카를로는 쓰지 않는다
* 이용자에게 칸을 하나씩 묻지 않는다 — 추천안을 채워 한 번에 확인받는다
* 계약서·조서·시나리오 같은 고객 자료를 저장소에 커밋하지 않는다
* 값 조서와 수식 조서의 결과가 다르면 건네지 않는다
