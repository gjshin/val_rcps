# 시장자료·부분상환·최종 확정 사용 안내

이번 변경은 기존 TF/GS·CB/BW/RCPS·주주간계약 계산 기능을 유지하면서 실무 검토 절차를 추가한다.
기존 전액상환 일정 분석은 「계약조건 분석 → 기존 전액상환 일정 분석」에서 계속 사용할 수 있다.
기존 평가파일은 새 필드를 비운 상태로 가져온다. 기존 파일의 검토 완료 표시는 새 통제 기준에서 다시 확인해야 한다.

## 1. 입력에서 먼저 확인할 것

1. 계약조건·시장자료를 입력하고 저장한다. 필수 입력을 임의의 수치로 채워 계산을 진행하지 않는다.
2. 「자료 출처·검토메모」에 계약서 조항과 S0·변동성·무위험/신용금리의 원자료 위치를 기록한다.
3. 「계약 반영표」에서 저장 입력과 계산 후 적용값을 비교한다. 확인할 행을 선택하여 조항, 반영방식, 근거, 확인자를 기록한다.
4. 「기본값·비적용 설정 확인」에서 보충값을 대조한다. 같은 기본값을 저장하는 것만으로 확인 완료가 되지 않는다.
5. 「시장자료 기준일 확인」에서 확인한 항목을 선택하고 기준일·검토자·근거를 남긴다. 날짜가 맞아도 자료의 적합성 판단은 별도로 필요하다.

별도 권리는 계약 반영표에서 ‘기본 모형 입력’으로 확인할 수 없다. ‘미해결’ 권리는 최종 확정을 막는다.
‘평가 제외’는 중요성·계약 해석의 근거가 필요하고, ‘입력 가정으로 근사’는 실제로 연결한 가정의 값과 검토근거를 확인해야 한다.
조건부 분석을 수행했다는 사실만으로 기본 평가에 반영된 것이 되지 않는다.

검토기록은 현재 입력·출처·별도 분석 입력·계산 코드에 연결한다. 이들이 바뀌면 다시 확인해야 한다.
기록 갱신만 필요하면 기존 수치를 재사용하며, 계산 입력 또는 코드가 바뀌면 다시 평가한다.

## 2. 변동성 자동 산출

「변동성 산출」에서 다음 순서로 진행한다.

1. 상장사 자체 주가 또는 비상장사 피어를 선택한다.
2. Yahoo 종목코드와 이름을 입력하거나 날짜·종목별 수정종가 파일을 선택한다.
3. 조회 종료일을 평가기준일로 맞추고 관측치 수, 연 거래일수, 이상치 제거 여부, 종합 방법을 정한다.
4. 「주가 받기」 또는 「파일을 현재 조건으로 읽기」를 누른다.
5. 종목별 관측기간, 제외된 수익률 수, 변동성을 확인하고 현재 평가에 적용한다.

종목·기준일·관측치 수·파일 내용이 바뀌면 다시 읽어야 한다. 파일명과 크기가 같아도 내용이 바뀌면 다른 파일로 식별한다.
연 거래일수·이상치 제거·종합 방법만 바뀌면 동일한 원자료에서 다시 산출한다.

일부 피어 수신 실패, 요청 관측치 부족, 중복·역순·미래 날짜, 0·음수·비유한 주가, 기준일보다 7일 넘게 오래된 최종 주가를 허용하지 않는다.
7일은 휴장·거래정지·수신 누락을 점검하기 위한 앱의 통제 기준이며 회계기준의 요건이 아니다. 해당 상황은 기간·피어·원자료를 검토한 후 다시 준비한다.
파일은 첫 열 날짜, 이후 한 개 이상의 종목별 주가를 사용한다. 완전한 역순 자료는 날짜순으로 정리하고, 잘못된 행·빈 셀을 조용히 제외하지 않는다.

계산은 로그수익률의 표본표준편차 × √연 거래일수이며, 선택 시 기존 MAD 이상치 제거 방식을 사용한다.
통계적으로 제외되었다고 경제적으로 부적절한 관측치라는 뜻은 아니다. 피어 선택과 이상치 제외의 근거를 남긴다.
원자료, 조회 조건, 선택된 옵션, 취득시각, 재산출값, SHA256을 평가파일·조서에 함께 보관한다. SHA256은 변경을 식별하며 자료 제공자의 진위를 인증하지 않는다.

새 평가 작업에서는 조회 이력이 없는 V1 변동성 패키지를 적용하지 않는다. 새 화면에서 재산출한다.
기존 명령행 도구는 V1을 경고와 함께 읽을 수 있으나, 새 최종 확정 절차를 적용한 산출물은 아니다.

## 3. 부분상환·지급시차·누적배당

「계약조건 분석 → 부분상환·지급시차·누적배당」에서 분석을 만든다.
현재 평가의 필수 입력이 완성되어야 하며 RCPS·TF만 지원한다.

| 입력 | 의미 |
|---|---|
| 분석 종료일 | 잔존 물량의 최종 전환 또는 상환청구 시점. 계약 만기보다 이른 종료는 지원하지 않음 |
| 기초 미지급배당 | 기준일 잔존 물량의 원금 100당 미지급 잔액 |
| 기초 기지급배당 누적 | 남은 각 주식에 귀속되는 과거 지급배당의 원금 100당 합계 |
| 미지급배당 가산이율 | 별도 약정이 있을 때만 입력. 상환이율이나 지연배상률을 자동으로 사용하지 않음 |
| 상환이율 | 발행일부터 청구일까지 실제일수/365, 연복리 적용 |
| 상환 시 미지급배당 | 약정 상환금에 이미 포함됐는지, 별도 가산하는지 선택 |
| 연장 중 권리 | 연장 중 전환권·상환청구권의 존재를 각각 명시 |
| 배당 발생·지급 | 해당 사건일 현재 잔존 물량의 원금 100당 금액 |
| 상환비율 | 해당 사건일 잔존 물량 중 청구 비율. 절반이면 0.5, 나머지 전량이면 1 |
| 실제 지급일 | 청구일부터 지급일까지 할인. 청구 이후 해당 물량은 전환할 수 없다고 가정 |
| 이익·현금 한도 | 최초 분석 물량의 원금 100당 금액. 해당 회차·지급건에 배분 가능한 금액 |
| 조정 전환가액 | 확정 또는 가정한 사건 후 주당 전환가액. 0이면 유지 |
| 지연 가산 | 가산 연이율과 시작일을 모두 명시. 12%는 일정표에서 0.12 입력 |

각 사건일의 예정 상환액은 다음과 같다.

`잔존 원금 100당 상환금 = 100 × (1 + 상환이율)^(발행일→청구일 실제일수/365) − 차감 대상 기지급배당 + 별도 가산 대상 미지급배당`

이 금액에 최초 물량 대비 해당 상환비율을 곱하고, 명시한 지연 가산을 반영하여 실제 지급일에 할인한다.
배당 지급은 같은 날 상환·전환 비교보다 먼저 발생한다고 가정한다. 이 사건 순서와 청구 후 권리 소멸이 실제 계약과 다르면 이 분석을 그대로 적용할 수 없다.

예를 들어 최초 물량 100% 중 40%를 먼저 청구하고 다음 해 나머지를 전량 청구하면 상환비율은 첫 행 0.4, 둘째 행 1이다.
현금흐름 대사표에는 최초 물량 대비 40%, 60%로 표시된다. 둘째 행에 0.6을 입력하면 잔존 60%의 60%인 36%만 추가 청구된다.

각 지급건의 이익·현금 한도가 지급액보다 작으면 계산을 중단한다. 한도를 여러 지급건에 중복 배분하지 않았는지 평가자가 별도로 대사한다.
현재 버전은 회사 전체 이익·현금의 시간별 공동 예산을 자동 관리하지 않는다.

일정은 기준일 이후 날짜순으로 입력하고 종료일 행을 포함한다. 상환 없는 행의 지급일·가산 시작일은 비운다.
상환청구 종료일 뒤의 실제 지급도 할인한다. 이미 기준일 전에 청구된 미수금은 잔존 RCPS와 구분하여 별도로 평가한다.

청구 전 전환과 예정 상환을 비교하고, 청구한 물량은 전환권에서 제외한다. 이후 잔존 물량을 전환해도 앞서 확정된 상환 미수금이 없어지지 않는다.
상환비율은 사용자가 입력한 조건부 일정이다. 주가별 최적 상환비율이나 이익·현금·주가의 공동 확률모형을 구한 결과가 아니다.
콜·정기 리픽싱·IPO·BDT 조건과의 결합은 차단한다. 청산배분·회차 간 상호 희석·계약위반 발생확률도 포함하지 않는다.

주가 비교는 동일 시간 간격의 격자에 사건을 이연하여 적용한다. 같은 격자에 두 사건일이 겹치면 간격을 줄여야 한다.
고정 현금흐름은 실제 날짜로 할인하도록 조정하지만, 전환·상환 비교에는 격자 근사가 남는다. 간격을 줄인 결과와의 수렴 대사가 필요하다.
부동소수점 오차 수준의 동률(비교금액 × 1e-12 이내)은 예정 일정의 계속보유로 처리한다. 동률에서 임의로 전환하여 TF의 현금·주식 할인 갈래가 바뀌는 것을 방지한다.
결과 화면의 최대 사건일 이연과 신용금리곡선 밖 지급일 여부를 확인한다.

## 4. 검토와 최종 값 조서

검토용 조서는 기존과 같이 저장할 수 있다. 최종 확정은 별도 절차다.

1. 현재 입력으로 평가한다.
2. 계약 반영표·시장자료·기본값 확인과 관련 판단 주제의 검토를 완료한다.
3. 「조서 → 독립 검산값과 대사」에 별도 계산서 위치·산식·허용차이와 원금 100 기준 검산값을 입력한다.
   앱 결과를 그대로 복사해 독립 검산이라고 기록하지 않는다. 일반 상품은 순포지션, SHA는 풋·콜을 각각 대사한다.
4. 앱 결과와 독립 검산값의 차이가 `max(절대 허용차이, |검산값| × 상대 허용차이)` 이내인지 확인한다.
   허용차이의 중요성 근거도 기록한다. 통과 여부는 숫자로 계산한다.
5. 작성자와 다른 검토자가 적용입력·정규화·경고·계약 제외/근사·산식·조서를 확인하고 검토결론을 남긴다.
6. 「현재 결과 최종 확정」 후 「최종 값 조서 생성」을 누른다.

다음 상태에서는 확정할 수 없다: 미해결 권리, 조건부 분석만 수행한 권리, 누락된 근거, 변경 전 검토기록, 입력 오류,
독립 검산 차이, 미완료 판단 주제, 보충 기본값 미확인, 시장자료 불일치, 작성자와 검토자 동일.
입력·출처·코드·검토기록을 바꾸면 최종 확정은 무효화된다. 입력만 바뀌지 않았다면 재계산 없이 검토기록을 갱신할 수 있다.

‘최종’은 기록된 검토절차가 완료된 기본 모형의 값 조서다. 조건부 분석을 자동 합산하지 않는다.
이름은 사용자가 입력한 검토기록이며 본인인증·전자서명·변조불가 감사로그가 아니다. 앱이 평가의견을 보증하지 않는다.
최종 조서는 값으로만 제공한다. 상세 수식 조서는 검토용이며 Microsoft Excel 전체 재계산 검증을 수행한 파일이 아니다.
여러 회차 묶음도 독립 회차의 검토용 산술 합계로 유지한다.

## 5. 검증 범위

`tests/test_practical_controls.py`는 독립 표본표준편차, 지급일별 현금흐름 현재가치, 부분상환 후 전환권,
작은 이항격자의 전환 선택, 누적배당·배당 차감·지연 가산·윤년 행사일을 대조한다.
원자료 변조·조회조건 변경·미완료 검토·확정 후 입력 변경·CLI의 확정본 차단/재현도 확인한다.
기존 세 업무 회귀 파일은 CB/BW/RCPS/SHA 결과, 기본/상세/수식 조서, 메뉴별 불필요한 재계산 방지를 검사한다.

이는 합성 입력의 독립 산식·회귀 검증이다. 고객별 계약 해석, 실제 시장자료 대조, 실제 Microsoft Excel 전체 재계산,
운영 서버 배포 확인까지 수행한 기록으로 확대 해석하지 않는다. 이번 변경은 새로운 시장자료를 임의로 채워 고객 평가액을 확정하지 않는다.

이번 소스에서 기존 업무 회귀 103건과 새 검증 45건, 총 148건이 한 번의 실행에서 통과했다.
검증한 소스의 SHA256은 `실무통제_검증기록.json`에 기록했다.
공개 종목의 Yahoo 실제 수신 점검은 HTTP 429 요청 제한으로 완료하지 못했다. 이 환경에서 실시간 수신 성공을 확인했다는 의미가 아니며,
수신이 막히면 원자료 출처를 확인한 종가 파일을 사용해야 한다.
