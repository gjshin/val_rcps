# RCPS 평가 — 설계 결정 기록

CB 앱(`val_derivative`)을 옮겨 와 상품 스위치로 상환전환우선주를 평가한다.
2026-09-06 사용자와 확인한 결정이다. 참고 자료는 CB 책 부속예제 18종을 준용했다
(TF 4-1 · Backsolve 5-1 · 상환가액 산식 5-7 · 리픽싱 5-6). RCPS 전용 사례 파일은 없었다.

## 결정

| 갈림길 | 결정 | 구현 |
|---|---|---|
| 기준 금액 | 1주 발행가 = 100 | 전환가치 100·S/K 가 CB 와 같아 격자를 그대로 쓴다 |
| 회계 전제 | 전환권을 자본 / 부채 중 고른다 | CB 와 같은 `conv_class` |
| 주가 | 직접 입력 + 발행가 역산 | `backsolve()` — 전체 가치가 목표(100)가 되는 주가를 이분법으로 |
| 존속기간 만료 | 자동전환 / 상환 스위치 | `mat_mode`. 자동전환은 **전환권이 있는 격자에서만** 탄다 |
| 우선배당 | **계약에 따라 둘** — 상환가액 가산(기본) / 발행자 재량 | `div_mode`·`eff_cpn()`. 재량이면 격자와 상환가액 산식에서 0 (1032 AG37) |
| 발행자 상환권 | 격자 안 MIN(보유, 상환가액) | `issuer_call` → `k_w=1`. 제3자·트랜치·세 방법은 닫는다 |
| 회계 묶음 | 발행자 상환권이 있으면 상환청구권과 복합내재파생 | `k_sep = 0 if issuer_call else 1` (문단 B4.3.4) |
| 기말 재평가 | 공정가치 + 전기 장부금액 → 평가손익·분개 | `prev_deriv`·`prev_host`, `remeasure()` |
| 앱 구조 | 한 앱에 CB / RCPS 스위치 | `Terms.inst`, `lbl()` |

## 왜 자동전환을 부채 격자에서는 타지 않나

전환권을 뺀 부채(B0·B1)는 존속기간이 끝나도 보통주가 될 수 없다. 그러므로 부채요소는
「상환받는다」는 전제로 재고, 자동전환은 전환권의 한 갈래로 전체 가치(B2)에만 들어간다.
그렇지 않으면 B0 가 주식 선도계약(108 근처)이 되어 부채가 아니게 된다.
만기에 상환청구가 열려 있으면 주식과 상환금액 중 큰 쪽을 고른다 (동점이면 현금).

## 발행자 상환권은 어디서 재나 — 1032 문단 31·32

> 자본요소가 아닌 파생상품의 특성(예: 콜옵션)에 해당하는 가치는 **부채요소의 장부금액에 포함**한다.

그래서 **전환권을 자본으로 볼 때**의 배분은 발행자 상환권을 **전환권 없는 부채 격자**에서
잰 값(`full["ca_debt"]`, 수식 조서 `16c` 시트 → 결과 C26)으로 부채요소를 줄인다.
전체 격자에서 잰 콜(B2 − B3)은 전환 상승분을 자르는 값이라 부채에서 빼면 부채가 과소·자본이
과대가 되고, 풋보다 커지면 복합내재파생이 음수가 된다 (월 노드 시험에서 실제로 −5.67 이 나왔다).
**전환권이 부채**면 전환권·풋·콜을 전체 격자에서 하나로 재므로 B2 − B3 를 그대로 쓴다.

    예 — 월 노드 · 발행자콜: 콜(전체) 22.73 · 콜(부채 격자) 0.00
         전환권대가  전체 기준 34.55  →  부채 기준 11.82

## 우선배당 — 이자인가 배당인가 (1032 AG37)

> 배당은 상환 전까지 발행자의 **재량**에 따라 지급하는 비누적적 우선주는 **상환금액의
> 현재가치에 상당하는 부채요소**가 있는 복합금융상품 … 배당은 자본요소와 관련되므로
> 당기순손익의 분배로 인식한다. **그러나 지급되지 않은 배당을 상환금액에 가산하는
> 경우에는 금융상품 전체가 부채**에 해당하고 배당을 이자비용으로 분류한다.

| 계약 | `div_mode` | 부채 현금흐름 | 상환가액 산식 |
|---|---|---|---|
| 미지급 배당을 상환가액에 가산 (보장수익률 − 배당률) | 0 (기본) | 배당 포함 | (g − c) 로 차감 |
| 배당은 발행자 재량 · 상환가액과 무관 | 1 | 배당 제외 | c = 0 |

계약 배당률은 조서에 그대로 남고, `eff_cpn()` 이 계산에 쓰는 값을 정한다. 수식 조서는
가정의 「우선배당 처리」 셀을 바꾸면 트리와 상환가액이 함께 따라온다.

    예 — 배당 2% · 보장 6%: B0 52.76 → 50.54 · B1 82.40 → 82.45 (배당 차감이 없어 상환가액이 커진다)

## 투자자 상환청구권이 없으면 (AG25)

> 현금으로 상환할 수 있는 권리가 **발행자에게** 있는 우선주는 … 금융부채의 정의를 충족하지 못한다.

상환청구 기간이 비어 있으면 `validate()` 가 「자본이므로 이 앱의 배분이 맞지 않는다」고
알린다. 계산은 막지 않는다 — 발행자 상환권만 재는 용도가 있을 수 있어서다.

AG25 는 배당가능이익 부족으로 상환하지 못할 가능성이 있어도 **계약상 의무는 무효가
아니라고** 한다. 상법 345조 한도를 평가에서 무시하는 근거다.

## 순차 차감

    B0 우선주부채 (옵션 없음) → B1 +상환청구권 → B2 +전환권(자동전환 포함) → B3 −발행자 상환권

CB 의 유무가치비교법(한도 100%)과 정확히 같은 계산이다. 전환권이 자본이면
부채요소 = B1, 전환권대가 = 100 − B1 + 발행자상환권. 값 조서의 트리는 발행자
상환권이 걸린 실제 격자(B3)를 보인다.

## 검증

- CB 기준선 불변: 37.5208 · 73.1837 · 112.9426 · 11.3910 · 38.2073
- 수식 조서 RCPS (자동전환/상환 × 콜 × GS × 부채) 다섯 경우 엔진과 소수점까지 일치
- `조서대조`·`설정전수대조` 에 RCPS 케이스 추가

## 상환가액의 단리 (⑤)

「발행가에 연 X% **단리**를 가산」이라고 쓴 계약이 적지 않다. 복리 횟수 칸에 **0** 을
넣으면 할증금률이 `(g − c)·t` 가 된다 — `accrue_rate` 의 g→0 극한과 같은 식이다.
만기·상환청구·발행자 상환 셋이 같은 함수를 쓰므로 한 곳만 갈라 놓았고, 수식 조서는
`xl_prem()` 이 같은 갈래를 엑셀 식으로 낸다 (거짓 갈래의 0 나누기를 막으려 `MAX(1, m)`).

    연 8% · 5년 · 표면 0%:  단리 140.00 · 연복리 146.93 · 반기 148.02 · 분기 148.59

계약서 숫자를 실효 복리율로 환산해 넣던 우회가 필요 없다.

## 거래원가 (⑦) — 1032 문단 38

> 복합금융상품 발행과 관련된 거래원가는 **배분된 발행금액에 비례하여** 부채요소와
> 자본요소로 배분한다.

분모는 복합금융상품에 배분된 **양수** 줄의 합이다. 매도청구권 자산은 별도의
금융상품이라(문단 4.3.1) 분모에서 뺀다. 배분한 몫의 처리는 그 요소의 회계원칙을 따른다.

| 요소 | 처리 |
|---|---|
| 주계약 · 부채요소 | 부채에서 차감 → **유효이자율에 녹는다** (`acc_host` 가 그만큼 낮은 데서 출발) |
| 파생상품부채 · 복합내재파생 | **즉시 비용** — 당기손익-공정가치라 거래원가를 얹을 자리가 없다 (1109 문단 5.1.1) |
| 전환권대가 | 자본에서 직접 차감 |

수식 조서는 가정의 「발행 거래원가」 셀을 바꾸면 배분표와 상각표 출발액이 함께 따라온다.
