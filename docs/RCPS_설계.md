# RCPS 평가 — 설계 결정 기록

CB 앱(`val_derivative`)을 옮겨 와 상품 스위치로 상환전환우선주를 평가한다.
2026-09-06 사용자와 확인한 결정이다. 참고 자료는 CB 책 부속예제 18종을 준용했다
(TF 4-1 · Backsolve 5-1 · 상환가액 산식 5-7 · 리픽싱 5-6). RCPS 전용 사례 파일은 없었다.

## 결정

| 갈림길 | 결정 | 구현 |
|---|---|---|
| 기준 금액 | 1주 발행가 = 100 | 전환가치 100·S/K 가 CB 와 같아 격자를 그대로 쓴다 |
| 회계 전제 | 전환권을 자본 / 부채 중 고른다 | CB 와 같은 `conv_class` |
| 주가 | 직접 입력 + 발행가 역산 | `backsolve()` — 전체 가치가 목표(100)가 되는 주가를 이분법으로 |
| 존속기간 만료 | 자동전환 / 상환 스위치 | `mat_mode`. 자동전환은 **전환권이 있는 격자에서만** 탄다 |
| 우선배당 | 확정 현금흐름 (표면이자처럼) | `cpn`·`ipay` 재사용. 상환가액 산식 (g−c) 에서도 그대로 차감 |
| 발행자 상환권 | 격자 안 MIN(보유, 상환가액) | `issuer_call` → `k_w=1`. 제3자·트랜치·세 방법은 닫는다 |
| 회계 묶음 | 발행자 상환권이 있으면 상환청구권과 복합내재파생 | `k_sep = 0 if issuer_call else 1` (문단 B4.3.4) |
| 기말 재평가 | 공정가치 + 전기 장부금액 → 평가손익·분개 | `prev_deriv`·`prev_host`, `remeasure()` |
| 앱 구조 | 한 앱에 CB / RCPS 스위치 | `Terms.inst`, `lbl()` |

## 왜 자동전환을 부채 격자에서는 타지 않나

전환권을 뺀 부채(B0·B1)는 존속기간이 끝나도 보통주가 될 수 없다. 그러므로 부채요소는
「상환받는다」는 전제로 재고, 자동전환은 전환권의 한 갈래로 전체 가치(B2)에만 들어간다.
그렇지 않으면 B0 가 주식 선도계약(108 근처)이 되어 부채가 아니게 된다.
만기에 상환청구가 열려 있으면 주식과 상환금액 중 큰 쪽을 고른다 (동점이면 현금).

## 순차 차감

    B0 우선주부채 (옵션 없음) → B1 +상환청구권 → B2 +전환권(자동전환 포함) → B3 −발행자 상환권

CB 의 유무가치비교법(한도 100%)과 정확히 같은 계산이다. 전환권이 자본이면
부채요소 = B1, 전환권대가 = 100 − B1 + 발행자상환권. 값 조서의 트리는 발행자
상환권이 걸린 실제 격자(B3)를 보인다.

## 검증

- CB 기준선 불변: 37.5208 · 73.1837 · 112.9426 · 11.3910 · 38.2073
- 수식 조서 RCPS (자동전환/상환 × 콜 × GS × 부채) 다섯 경우 엔진과 소수점까지 일치
- `조서대조`·`설정전수대조` 에 RCPS 케이스 추가

  전체 격자 기준(유무가치비교)이다
