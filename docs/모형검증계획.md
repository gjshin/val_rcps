# 모형 검증 계획 — val_rcps

「모든 경우의 수를 검증했다」는 말의 뜻을 먼저 정한다 — **지원하는 이산 분기 100%, 각
입력의 경계, 호환 옵션의 pairwise, 지정한 고위험 3-way, 실제 사례, 고정 seed 속성검증.**
숫자 입력의 무한한 데카르트 곱을 했다는 뜻이 아니다.

원칙 (작업지시서 §1.3)

1. 엔진 = 조서 일치는 증거가 아니다 — 둘이 같이 틀리면 통과한다. 그래서 독립 오라클이 있다.
2. 고치기 전에 실패하는 시험을 먼저 둔다 (손계산대조 [18] 처럼 「고치기 전 실패 → 고친 뒤 통과」를 남긴다).
3. 골든값을 덮어쓰지 않는다. 값이 움직이면 계약·산식·독립 계산으로 설명하고, 안 되면 결함이다.
4. 지원하지 않는 조합은 validate · 화면 · 조서가 같은 문구로 막는다 (`compat()`).
5. 허용오차는 항목마다 근거를 적는다 (`docs/골든값과_허용오차.md`).
6. 리팩터링과 산식 변경을 한 커밋에 섞지 않는다.

## 단계

| 단계 | 산출물 | 완료 기준 |
|---|---|---|
| 1 기준선 | `docs/검증기준선.md` | 기존 7 시험 실행 · 대표값 고정 · 화면↔엔진 틈 목록 |
| 2 기능 명세 | `tests/기능목록.py` → `tests/검증매트릭스.json` | 모든 스위치가 명세에 있고, 명세에 없는 스위치가 코드에 없다 (`--strict`) |
| 3 독립 안전망 | `tests/오라클.py` · `tests/분기전수.py` · `docs/골든값과_허용오차.md` | 미검증 갈래 0 · 독립 오라클 붙은 갈래 수 · P0 회귀 |
| 4 결함 재현·수정 | `compat()` · F-01~05 · 손계산대조 [19]·[20] | BLOCK 행이 세 경로 일치 · 매트릭스 FAIL 0 |
| 5 조합·속성 | `tests/조합시험.py` → `tests/output/조합시험.json` | pairwise 누락 0 · 3-way 전부 PASS/BLOCK/LIMIT · 무작위 500/상품 + 고위험 200 · 실패 seed 저장 |
| 6 조서·회계 | `model_checks()` · 조서 「검산요약」「99_모형검증」 · `MODEL_LIMITS` | 회계 등식(배분 합·차대·원가·상각) · 한계 문구 한 원본 |
| 7 최종 | `tests/run_all.py` → `tests/output/validation_result.json` · `docs/모형검증결과.md` | 깨끗한 환경 2회 실행 동일 · FAIL 0 · NOT_TESTED 0 |

## 네 층의 오라클

| 층 | 무엇 | 어디 |
|---|---|---|
| 독립 식 | 계약·교과서에서 곧바로 쓴 닫힌 꼴. `app.py` 를 보지 않는다 | `오라클.py` §A · `손계산대조.py` |
| 항등식 | 배분 합 100 · 분포 합 1 · 풋·전환·콜 ≥ 0 · q ∈ (0,1) · 상각표 기말 = 상환금액 · 분개 차대 · 원가 배분 합 | `분기전수.py` · `조합시험.py` · `model_checks()` |
| 단조성 | 전환가격↑ → 전환권↓ · 주가↑ → 전환권↑ · 하한↑ → 값↓ · 콜 프리미엄↑ → 콜↓ · 풋 금액↑ → B1↑ · 행사 불가 기간 불변 · 총액 배수 불변 | `조합시험.py` 4층 |
| 스냅샷 | 엔진 = 값 조서 = 수식 조서(`formulas` 재계산) | 값조서·조서·주주간계약·설정전수·리포트 대조 |

단조성이 이론적으로 성립하지 않는 자리는 강제하지 않고 이유를 적는다 (`골든값과_허용오차.md` §6):
자동전환·강제전환의 전환권, TF·GS 강제전환 할인율 효과의 매도청구권, 주주간계약 상호소멸의
우선순위, BDT 부채요소와 격자 B0·B2 의 비교.

## 실행

```bash
python3 tests/run_all.py --quick     # PR 전 (몇 분)
python3 tests/run_all.py             # 전체 (한 시간 남짓)
```

같은 코드로 두 번 돌려 `tests/output/validation_result.json` 이 (시간 필드 빼고) 같아야 한다.
조합시험은 seed 가 고정이라 같은 코드면 같은 결과다 — 실패는
`tests/output/조합시험_실패.json` 에 Terms 전체가 남아 그 줄만으로 재현된다.

## 이 계획이 하지 않는 것

- 숫자 입력의 전수 — 무작위 표본과 경계값으로 대신한다
- 화면(Streamlit) 자동 시험 — 화면은 `compat()` 상수와 `model_checks()` 를 그대로 쓰므로
  엔진·조서 시험이 화면 논리를 덮는다. 화면 배선은 손으로 확인한다
- 성능 회귀 — `validation_result.json` 의 시험별 시간을 사람이 본다
