# 판단 근거 연결과 평가용역 업무 개편

2026-09-28 작업. 기존 기능을 한 앱에서 사용하고, 수치와 판단의 근거를 함께 보관하도록 개편했다.
완료 여부는 기능 구현·계산 검증·실제 용역의 결론을 구분해서 확인한다.

## 사용 흐름

| 업무 | 사용하는 화면 | 처리 결과 |
|---|---|---|
| 계약·시장자료 입력, 기본 평가 | 평가 작업 | 저장 후 실행. 수정 전 결과와 현재 입력을 구분 |
| 회계분류·모형 선택 검토 | 판단 근거 | 12개 주제의 기준서, 실무사례 발췌, 원문 위치, 체크 질문, 검토자 기록 |
| 상환 제약·배당·연장·사건 조정 | 계약조건 분석 | 명시한 일정이 실현되는 경우의 조건부 분석과 현금흐름 대사표 |
| 여러 회차 평가와 취합 | 여러 회차·변동 분석 | 변경 회차 계산, 총괄표, 개별 조서, 재현 입력 묶음 |
| 전기 대비 차이 분석 | 여러 회차·변동 분석 | 기준일·계약·주가·변동성·금리·방법 순서의 변동 대사 |
| 역산, 금리 산출, 회계 참고표, 격자·검산 | 상세 기능 | 현재 평가 입력을 가져오고 변경표 확인 후 같은 평가에 반영 |
| 대상회사·피어 변동성 | 변동성 산출 | 기준일 대조 후 현재 평가에 적용, 산출 근거 기록 |

상세 기능도 선택한 분석 항목만 실행한다. 계산은 실행 버튼을 누른 후 수행하고 같은 입력의
결과를 세션에서 재사용한다. 상세 화면을 떠나면 대형 격자 캐시를 해제한다. 기존 독립 실행과
명령행 도구는 유지한다. 원래 계약값과 별도 가정은 상세 기능에서 돌아와도 구분된다.

## 근거의 구성

- 사용자 제공 한국공인회계사회 Series 11(2023): 짧은 발췌 13건, 책/PDF 쪽수, 파일 SHA256.
- K-IFRS 제1032호: 부채·자본, 복합상품 배분, 우선주 권리(AG25·AG26).
- K-IFRS 제1109호: 금융자산 주계약, 내재파생 분리, 별도 금융상품, 풋·콜 예외.
- K-IFRS 제1113호: 투입자료, 거래가격에 대한 보정, 평가기법의 일관성.
- 회계위키의 관련 해설은 기준서 본문과 구분해 표시한다. 공식 시행 기준서 링크도 제공한다.

기준서 수록 본문과 회계위키 해설을 대조했다. 한국회계기준원 시행 목록도 확인했으나, 이 작업이
모든 공식 PDF의 개정 전후 문구를 전수 비교한 작업은 아니다. 2023년 사례집의 해설을 현행
규정으로 일괄 간주하지 않는다. 주제 목록은 계약서 전체에 대한 검토를 대체하지 않는다.

검토 완료에는 검토자·결론·판단근거를 요구한다. 입력·출처·가정·추가 계약조건이 바뀌거나
근거 목록의 내용이 변경되면 재검토 표시한다. 단순히 근거를 열어 보았다는 이유로 완료 처리하지 않는다.
인증된 전자서명이 아닌 사용자가 기재한 검토기록이다. 화면, JSON, 기본·상세 Excel에 함께 남긴다.

실무사례 PDF 전체는 저장소에 포함하지 않는다. 사용자가 보유한 PDF를 올리면 해당 쪽만
추출해 확인할 수 있다. 다른 판본이면 쪽수 재확인 안내를 표시한다.

## 수정한 판단 규칙

| 기존 문제 | 현재 처리 | 확인 근거 |
|---|---|---|
| BDT의 정성적 설명을 4개 통과 조건·수치 경계로 바꿈 | ±5%p·0.2·70%에 따른 자동 결론 폐기. 관측값과 민감도를 제공하고 판단을 기록 | 책 87·89쪽 |
| 배당가능이익 부족과 부채·자본 분류를 혼동할 수 있음 | 계약상 의무의 분류와 실제 상환시점·금액의 측정을 구분 | 제1032호 AG25, 책 91·92쪽 |
| 실제 검토 없이 ‘검토했으나 적용하지 않음’ 문안 생성 | 검토 초안으로 표시하고 완료 결론을 작성하지 않음 | 전문적 판단의 문서화, 책 151쪽 |
| 상태확장 리픽싱을 수식 조서 작성 중 근사법으로 바꿈 | 같은 방법의 수식 조서를 만들 수 없으면 차단. 값 조서 사용 또는 명시적인 방법 변경 후 재평가 | 화면·조서 계산방법 일치 |
| 상세 조서와 새 검토기록이 분리됨 | 실제 상세 입력을 기준으로 판단 근거를 추가, 달라진 입력의 종전 검토는 재검토 표시 | 입력 식별값·근거 버전 |
| 새 형식의 평가파일을 기존 입력기로 열면 계약값이 기본값으로 바뀔 수 있음 | 형식을 확인하고 해당 화면·명령행 도구로 안내. 읽기 실패 시 계산 중단 | 저장 파일의 입력 보존 |

기존 계산부에서 바뀐 함수는 `bdt_review`와 `write_check_sheets`다. 가격결정·할인·격자 함수는
이번 작업에서 변경하지 않았다. 새 일정 분석은 별도 모듈이다. 기존 회계분류·분개 표는 입력 가정에
따른 참고 계산으로 남기며 모든 계약에 대해 올바른 회계의견을 자동 제공한다고 표시하지 않는다.

## 계약조건 분석의 계산 범위

RCPS·TF에서 날짜별 배당 발생·지급, 기초 미지급 배당과 연복리 가산이자, 종료일 연장,
전환 시 미지급 배당의 지급·소멸, 사건에 따른 전환가액 변경을 분석한다. 상환은 해당 회차에
배분된 배당 지급 후 가용이익·지급재원이 전액 상환금액을 충족할 때만 허용한다.

분석표가 기존 배당·상환 일정을 대체한다. 전환 행사기간은 현재 평가 입력을 사용한다.
미지급액은 먼저 누적·정산한 후 상환 또는 전환에 반영하며 이중 지급하지 않는다.
사건일은 이후 첫 격자에 반영하고 시차를 공개한다. 같은 격자에 사건일 두 개가 겹치면 계산을 막는다.

이 일정은 조건부 가정이다. 미래 이익·현금·사건 발생의 확률과 주가 사이의 공동분포를 추정한
모형이 아니다. 책 92쪽이 지적하듯 DCF 손익계획 한 가지를 모든 주가 경로에 적용하는 데에는
제약이 있다. 결과를 기본 평가값에 자동 합산하거나 확정 공정가치로 바꾸지 않는다.

현재 제외 범위는 콜·정기 리픽싱·IPO·BDT와의 결합, 부분상환, 청구일과 지급일 사이의 권리
소멸, 무기한·상태 의존 연장, 여러 종류주식의 청산우선권·상호 희석이다. 해당 권리가 입력되어
있으면 지원하지 않는 결합을 조용히 생략하지 않고 중단한다. 이런 계약의 최종 모형화와 보정에는
실제 계약·가용재원·자본구조·시장자료가 필요하다.

## 검증 기록

- 새 업무 흐름·근거·회차·일정 분석 시험: 103개 통과. 상세 조서의 계산 수식 유지, 파일 형식 오인식 차단,
  기존 명령행 도구에서 수식 조서를 만들기 위한 자동 근사법 변경 차단도 확인했다.
- 독립 손계산: 배당 누적·지급·이자, 종료 상환의 현금흐름 할인, 이항분포 옵션값, 전환가액 변경,
  상환재원 제한, 전환 시 미지급 배당 처리, 기간 연장을 대조했다.
- 화면: 6개 업무 경로와 기존 상세 10개 분석 항목을 열고 평가 작업으로 돌아오는 흐름을 확인했다.
- 판단 규칙 수정 후 손계산·기능목록·리포트 대조 통과. 기준선 37.5208 / 73.1837 / 114.8781 / 13.0762 일치.
- 기존 기능목록의 최초 실패 22건은 README에서 사라진 한계 안내였다. 안내를 복원한 후 401행 검사를 통과했다.
- 기존 조합시험 전체: 4,936건, 실패 0. 전체 수식·설정 대조의 최종 결과는 `전체검증_최종기록.json` 참조.
- 기존 실제 사례 3건: 보완 입력에서 새 서비스와 기존 계산부 결과 차이 0. 각 계약의 실제 공정가치를 독립 입증한 시험은 아니다.
- RCPS 2개 예시에 빠진 주당 발행가는 기존 사례 문서의 81,000원·17,354원으로 명시적으로 보완했다.
  다른 시장·계약 가정은 유지했다. 사례 원 공시와 계약을 이번에 다시 입수해 전수 확인한 것은 아니다.

수식 대조는 Python `formulas`로 수행한다. 일부 지원하지 않는 함수·시트 이름은 기존 시험의
변환 절차를 거치며 격자도 축소한다. 사용자의 전체 크기 파일을 Microsoft Excel에서 직접
재계산한 것과 동일한 검증은 아니다. 최종 제출 파일은 실제 사용하는 Excel 환경에서 확인해야 한다.

60구간 예시에서 근거 기록 갱신 0.024초, 기본 조서 0.652초이고 둘 다 추가 주가 격자 계산은 0회였다.
상세 조서 18.354초와는 포함 범위가 다르다. 단일 실행·Python 메모리 추적 환경의 측정값이며
모든 계약의 처리시간이나 기존 가격결정 산식 자체의 속도 개선을 의미하지 않는다.
