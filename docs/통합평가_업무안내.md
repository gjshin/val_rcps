# 통합 평가 화면 및 계약 검토 업무

화면 버전: `2026.09.29-unified.1` / 변경 기준: `fcb09fc`

## 기존 앱의 취지와 이번 변경

기존 앱은 CB 이항격자에서 출발하여 RCPS·BW·주주간계약으로 확장된 도구다.
`docs/RCPS_설계.md`, `docs/책예제_대조표.md`, `docs/책근거_대조.md`,
`docs/사례목록_2026-09.md`, `docs/의사결정규칙.md`와 현재 계산 코드를 함께 확인했다.
초기 설계 문서는 당시 미구현 기능을 포함하므로 현재 지원 여부는 코드와 회귀시험으로 판단한다.

- TF·GS, 상환권의 BDT, 콜 유무 가치 비교 및 옵션차익 방식은 서로 다른 평가 전제와 대상이 있다. 화면 통합을 이유로 계산방법을 하나로 바꾸지 않는다.
- 발행자 상환권, 제3자 지정 가능 콜, 사전 특정 콜의 구분 및 의무보유·권리 소멸 조건을 유지한다.
- 구성요소 순차 차감, 전체 공정가치, 회계상 인식·배분액을 구분한다. 투자자와 발행자 관점도 유지한다.
- 계약상 분류와 실제 지급시점·회수금액의 측정은 구분한다. 배당가능이익·현금 제약, 미지급 배당 이월, 사건형 조정은 기본 격자에 자동 반영되는 것으로 표시하지 않는다.
- 기존 계산엔진 `valuation/legacy.py`의 수식은 수정하지 않았다. 상시 행사 설정을 엔진에 전달하는 입력 해석과 업무 화면을 보완했다.

## 한 평가파일로 작업하기

왼쪽 메뉴는 **평가 작업**, **여러 회차·변동 분석**이다. 단일 계약의 상세 입력·분석을 위해 평가파일을 복사하거나 다른 화면에 가져올 필요가 없다.

| 작업 | 위치 | 처리 방법 |
|---|---|---|
| 계약별 입력안·원문 조항 검토 | 계약 검토 | 조항별 해석, 연결 입력값, 추가 자료 확인 |
| 기본 및 상세 조건 | 입력·시장자료 → 계약·평가 입력 | 입력값을 현재 세션의 평가파일에 바로 반영 |
| 시장자료 산출·조회 | 입력·시장자료 → 주가·변동성·금리 자료 | 도구별 실행 후 현재 평가에 적용 |
| 계약과 다른 가정·미반영 권리 | 입력·시장자료 → 출처·평가가정 | 원본 사실과 별도 가정을 구분하여 기록 |
| 평가 실행 | 평가·분석 | 현재 입력으로 평가 버튼. 단순 화면 이동으로 계산하지 않음 |
| 상세 계산·회계 참고표 | 평가·분석 → 분석 도구 | 기존 입력과 계산 결과 공유. 별도 가져오기·반영 없음 |
| 상환제약·기간연장 등 비교 | 평가·분석 → 계약조건 시나리오 | 입력한 조건부 시나리오를 기본 평가와 구분 |
| 계약·회계 판단 | 검토조서 → 계약·회계 판단 | 관련 입력, 검토할 사항, 후속 작업, 발췌문, 결론 기록 |
| 계약 반영표·시장자료 기준일 | 검토조서 → 입력 적정성 | 계약별 반영 여부와 보충 기본값 확인 |
| 독립 검산·검토자 확인 | 검토조서 → 독립 검산·승인 | 독립 값과 허용차이 대사 후 승인 |
| 검토용·최종 조서 | 조서 출력 | 입력·근거·계산 결과·검토기록 보관 |
| 여러 회차·부분상환·변동요인 | 왼쪽 여러 회차·변동 분석 | 기존 여러 평가파일 및 일정 분석 사용 |

입력은 **현재 앱 세션**에 반영되며 영구 저장을 뜻하지 않는다. 종료 전 왼쪽 **평가파일 저장**으로 JSON을 보관한다. 세션 재연결·새로고침·서버 재시작에 대비해야 한다.

수치가 바뀌면 종전 결과는 변경 전 입력의 결과로 표시되며 조서 생성이 차단된다.
출처·검토기록만 바뀌면 기존 계산값을 재사용한다. 민감도·상세 검산 등 선택한 분석은 추가 계산할 수 있다.

## 언제든지 행사할 수 있는 계약

- 투자자 상환청구, 발행자 콜, 제3자 콜, 주주간계약 풋·콜에서 **정기 행사·조정 / 기간 중 언제든지**를 선택한다.
- 전환·신주인수권은 **기간 중 언제든지 / 특정일에만 행사**를 선택한다. 특정일은 행사 시작일을 사용한다.
- 전환가액 조정에도 정기 조정과 기간 중 언제든지 조정을 구분한다.
- ‘언제든지’는 **입력한 행사기간 내 모든 계산시점**에서의 행사를 뜻한다. 연속시간 해석의 정확한 해를 뜻하지 않는다. 계산 간격을 줄여 민감도를 확인한다.
- 기존 파일에 행사주기 숫자만 있으면 상시 행사 의도를 자동 추정하지 않는다. 원문상 상시 행사라면 해당 방식을 직접 선택한다.
- 계산 간격이나 잔존기간이 바뀌어도 상시 행사 선택은 유지된다. 단기 잔존기간의 최소 4구간 격자도 반영한다.
- 회차별 금액표는 기존 엔진에서 행사일도 지정한다. 상시 행사와 함께 입력하면 충돌로 차단한다. 금액 변경일만 규정한 표를 행사일 제한으로 오인하지 않아야 한다.
- 계약상 통지일·효력 발생일·결제일은 서로 다를 수 있다. 이 선택만으로 통지기간이나 결제 지연이 자동 구현되지는 않는다.

## 변동성 적용

**입력·시장자료 → 주가·변동성·금리 자료 → 변동성 산출**에서 종목·종료일·관측기간을 정하고 자료를 조회한다.
결과 확인 후 **이 변동성을 현재 평가에 적용**을 누르면 `sig`와 주가 원자료·조회조건·산출근거가 함께 저장된다.
주당가치·금리 등 다른 필수값이 비어 있어도 적용할 수 있다. 평가기준일도 비어 있으면 변동성 증빙만 저장하고 기준일을 임의로 채우지 않는다.
기준일이 이미 입력되어 있는데 조회 종료일과 다르면 적용하지 않는다. 계산·최종 확정 전 기준일 일치를 확인한다.

조회 종목·기간·기준일을 바꾸면 재조회해야 한다. 일부 피어 조회 실패 시 이전 산출값을 대신 적용하지 않는다.
Yahoo Finance가 제한·실패하면 수정종가 파일로 산출할 수 있다. 실제 외부 조회의 성공은 데이터 공급자의 응답에 따라 달라진다.

기준일 주가 조회, 거래가격을 이용한 주가 역산, KIS-Net 금리표·표 붙여넣기, BDT 금리 시계열 산출도 같은 위치에서 사용한다.
주가 역산은 거래가격의 적정성에 대한 판단을 대체하지 않으며, 산출값 적용 시 근거를 기록한다.

## 업무파트너와 계약서 검토

계약서를 앱의 외부 AI API로 보내는 기능은 추가하지 않았다. 이 대화에서 자료를 검토한 뒤 앱에 입력안을 가져오는 흐름이다.

업무파트너가 준비할 산출물:

1. 조항·쪽수·원문 발췌와 계약 해석
2. 앱 항목별 입력값·단위·입력 위치 및 근거
3. 별도 가정, 기본 모형 미반영 권리, 필요한 조건부 분석
4. 기준서·실무사례와 연결한 검토 초안 및 평가자가 확정할 사항
5. 미확인 조건과 추가로 요청할 자료
6. 앱에 불러올 평가 입력파일 JSON

계약서로 확인되지 않는 주가·변동성·금리·실제 납입일 등을 임의로 채우지 않는다.
검토 초안은 검토 완료 기록으로 자동 승격되지 않는다. 추가 확인사항이 남아 있으면 최종 확정을 차단한다.
확인사항을 처리할 때 확인자·자료·결과를 기록하며, 판단 결론은 검토조서에 별도로 남긴다.

고객 원문·추출 내용·고객별 입력안은 공개 저장소에 커밋하지 않는다.
앱 입력파일에도 고객 정보와 조항 발췌가 포함될 수 있다. 사용자 또는 조직이 승인한 앱 서버와 저장 위치를 사용한다.
Streamlit 앱으로 가져온 파일은 해당 앱 서버가 처리한다. ‘외부 AI 전송 없음’이 ‘서버 전달 없음’을 의미하지 않는다.

## 검토안의 데이터 형식

기존 `valuation-case/2`는 그대로 읽는다. 선택 항목 `exercise_styles`, `contract_review`를 추가했다.
실무 입력파일은 기존 `contract`·`market`·`method`·`sources`에 입력값을 넣고, 검토안은 아래와 같이 연결한다.
이 구조 예시는 고객 자료가 아니다.

```json
{
  "exercise_styles": {"p_f": "any", "k_f": "any", "cv": "any"},
  "contract_review": {
    "documents": [{"name": "자료 식별명", "sha256": "원본 파일의 SHA256 64자리 소문자 16진수"}],
    "findings": [{
      "document": "자료 식별명",
      "clause": "제X조, PDF Y쪽",
      "quote": "검토에 필요한 원문 발췌",
      "fields": ["p_s", "p_e"],
      "topics": ["redemption_constraint"],
      "interpretation": "계약 해석 초안",
      "action": "확인할 사실 및 입력 반영방법"
    }],
    "open_items": ["추가로 확인할 자료"]
  }
}
```

## 확인 범위

수치 계산엔진은 기존 것을 공유한다. 입력 해석·저장·화면·출력에 대한 회귀시험과 합성 계약의 손계산 대사를 수행했다.
검증 결과는 `통합평가_검증기록.json`에 기록한다. 모든 실제 계약·공시조건을 검증했다는 뜻은 아니다.
통합 격자에서 직접 다루지 않는 조건부 권리, 다종류주식 배분, 행사 통지·결제 지연은 추가 검토가 필요하다.
Excel 수식의 실제 Excel 재계산 및 운영 Streamlit 서버의 재배포 완료 여부는 별도 확인 사항이다.
