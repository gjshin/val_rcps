# 골든값 출처와 허용오차 — 모형 검증 프로그램 3단계

`docs/검증기준선.md` 가 「무엇을 재는가」라면 이 문서는 「기대값이 어디서 왔고 얼마나
어긋나도 통과인가」다. 시험을 더하거나 고칠 때 이 표에 맞춘다.

## 1. 기대값의 세 출처

| 출처 | 뜻 | 어느 시험 | 갱신 규칙 |
|---|---|---|---|
| **독립 식** | 계약·교과서에서 곧바로 쓴 닫힌 꼴. `app.py` 를 보지 않는다 | `tests/오라클.py` §A · `tests/손계산대조.py` | **엔진을 고쳤다고 갱신하지 않는다.** 어긋나면 계약을 다시 읽는다 |
| **항등식** | 어느 갈래에서나 성립해야 하는 관계 (배분 합 100, 분포 합 1, 풋·전환·콜 ≥ 0, q ∈ (0,1), 상각표 기말 = 상환금액, B0+풋+전환 = B2) | `tests/분기전수.py` · `오라클.py` [I] · `손계산대조.py` 여럿 | 갱신할 것이 없다 |
| **스냅샷** | 엔진 값을 조서(값·수식)가 그대로 싣는가 — **엔진이 틀리면 같이 틀린다** | `값조서대조` · `조서대조` · `주주간계약대조` · `설정전수대조` · `리포트대조` | 엔진이 바뀌면 바뀐다. 그래서 위 두 출처가 따로 있다 |

`검증기준선.md` §3 의 대표값(기본 계약 37.5208 · 73.1837 · 114.8781 · 12.2404, 대신증권·
차바이오텍)은 **스냅샷**이다 — 「그때 그 코드가 낸 값」이지 정답 증명이 아니다. 그
값이 움직이면 결함이거나 의도한 산식 변경이고, 어느 쪽인지는 독립 식이 가른다.

## 2. 허용오차 — 항목별 근거

| 항목 | 허용오차 | 근거 |
|---|---:|---|
| 이자율·확률 (u, d, q, 연속환산, 할증금률) | 1e-12 | 같은 식이면 기계 오차뿐이다 |
| 금액 100 기준 — 독립 식 대 격자 | 1e-6 | 같은 부동소수 연산을 다른 순서로 한다. 실제 차이는 1e-9 안팎 |
| 금액 100 기준 — 항등식 (풋·전환·콜 ≥ 0) | −1e-7 | 뺄셈 두 번의 잡음. 실제 0 인 자리에서 −1e-14 가 나온다 |
| 배분표 합계 100 | 1e-9 | 단순 덧셈 |
| 정산 분포 합 1 | 1e-9 | 확률 곱셈·덧셈 n 회 |
| 상각표 마지막 기말 = 상환금액 | 1e-6 | 유효이자율 이분법 200 회 (1e-15 수준) 뒤 n 회차 누적 |
| 전환가격 (원) | 1e-6 | clip 과 소수 6 자리 반올림 (상태확장 열쇠) |
| 스냅샷 — 조서 대 엔진 | 1e-4 (값조서대조는 1e-6) | 수식 조서는 소수 4 자리로 싣는다. `formulas` 재계산도 같은 자리. 값 조서는 원값이라 더 조인다 |
| 리포트대조 | 상대 1e-9 | 변동성·이자율은 자리수가 제각각이라 상대오차 (`TOL = 1e-9`) |
| 역산 (`bs_target`) | 0.25 | 격자 값이 주가에 대해 **불연속**이다 — 노드 하나가 넘어갈 때 0.19 가 뛴다. 그 안이면 도달한 것 |
| 날짜 → 노드 | 0 (정수) | 노드 번호는 정수. 어긋나면 하루가 아니라 한 노드다 |

허용오차를 넓혀서 통과시키는 일은 **없다.** 넓혀야 하면 여기 줄을 더하고 이유를 쓴다.

## 3. 관행 선택 — 결함이 아니라 정의

독립 식을 쓰다 보면 「계약이 이렇게도 저렇게도 읽히는」 자리가 나온다. 이 앱이 고른
쪽을 적어 둔다. 바꾸려면 엔진·조서 수식·입력 안내를 같이 바꿔야 한다.

| 자리 | 이 앱의 선택 | 다른 읽기 | 어디 |
|---|---|---|---|
| 회차가 정수가 아닌 복리 할증금 (연 1회 복리 · 3.5년) | 지수를 분수로 잇는다 (1+g)^3.5 | 완결 회차 3 + 단리 반년 | `accrue_rate` · `xl_prem` · `오라클.py` [C] |
| 만기 노드 동점 (전환가치 = 상환금액) | 현금 (전환은 +1e-9 앞설 때만) | 전환 | `의사결정규칙.md` §4 |
| 만기까지 열린 풋의 마지막 노드 | 만기 노드 n 포함 | n−1 까지 | `step_mapper` · `오라클.py` [J] |
| 노드가 계약일과 며칠 어긋날 때 | 간격의 ¼(최대 5일) 안이면 같은 날 | 엄격 비교 | `step_mapper` |
| 상장 스텝 자식 전환가격 | 공모가×배수로 자른 뒤 하한·상한 clip | — | `child_k` |

## 5. 4단계에서 고친 것 — 화면·validate·직접 호출이 같은 답을 낸다

| ID | 무엇 | 전 | 후 | 잠금 |
|---|---|---|---|---|
| **F-01** GS + 매도청구권 평가방법 1·2 | 화면만 잠갔다. 코드로 직접 부르면 경고 없이 다른 값 (매도청구권 8.9862 / 9.1886, 화면 강제값 12.2404) | `compat()` 이 `k_method=0` 으로 되돌리고 `validate()` 가 같은 문구(`COMPAT_GS_KMETHOD`)로 알린다. 화면 캡션도 같은 상수 | `손계산대조 [19]` |
| **F-02** 전환권 부채(또는 콜 내재파생) + 조기상환권 미분리 | 화면만 잠갔다. 값은 같았지만 설정을 조용히 버렸다 | `p_sep=1` 되돌림 + 경고 (`COMPAT_PSEP`) | `[19]` |
| **F-03** GS 또는 전환권 부채 + BDT | 위와 같다 | `put_bdt=0` 되돌림 + 경고 (`COMPAT_BDT`) | `[19]` |
| **F-06** RCPS 배분표가 100 에 안 닿는다 (99.9236) | 매도청구권이 음수(모형 성질)일 때 그 줄을 빼면서 잔여 계산에는 넣었다 | 값이 0 이 아니면 줄을 싣는다 (`allocate()` 네 갈래) | `조합시험.py` alloc_100 |
| **F-05** 유효이자율이 상한 500% 에 걸리고, 잔여 주계약 ≤ 0 에서도 상각표를 만들었다 | 만기 한두 달 앞 중간평가에서 연 환산 유효이자율이 500% 를 넘으면 이분법이 상한에서 멈춰 기말이 상환금액과 안 맞았다. 부채 분류에서 잔여 주계약이 음수면(Day-1 차이) 엉터리 표가 조서에 실렸다 | 상한을 현재가치가 장부금액 아래로 갈 때까지 네 배씩 올리고(최대 연 1e7), 하한은 −99% 다 — 만기 한두 달 앞에서는 연 환산이 극단이 된다. 잔여 ≤ 0 이면 `acc_host()` 가 None — 화면·조서가 같은 뜻의 문구(`HOST_NONPOS_NOTE` · `HOST_NONPOS_XL`)를 싣는다 | `조합시험.py` amort_end · 랜덤 |

스냅샷 케이스 아홉(값 조서 8 · 수식 조서 1)이 GS + 평가방법 1·2 를 담고 있었다. 화면에서는
애초에 만들 수 없던 조합이라 골든값이 아니라 **도달 불가능한 스냅샷**이다 — 이제 되돌린
값(평가방법 0)으로 엔진과 조서가 함께 움직이고, 케이스는 그대로 두어 «되돌린 뒤에도 조서가
엔진을 따라오는가» 를 본다.

## 6. 5단계 첫 실행에서 나온 것 — 결함이 아닌 모형 성질 (KNOWN_LIMITATION)

| 자리 | 무엇 | 왜 결함이 아닌가 | 시험의 처리 |
|---|---|---|---|
| 자동전환·상장 강제전환 RCPS | 전환권 = B2 − B1 < 0 | 그 전환은 권리가 아니라 **의무**다. 주가가 낮으면 상환(B1)보다 못하다 | `conv_ge_0` → limit |
| TF·GS 의 강제전환 할인율 효과 | 유무가치비교법 매도청구권 < 0 (콜 있는 격자 > 없는 격자) | 콜이 전환을 강제하면 그 노드가 부채(위험 할인)에서 지분(무위험·전환확률 할인)으로 바뀐다. 할인이 가벼워져 부모 값이 **오른다**. TF 논문의 알려진 성질. RCPS 발행자 상환권은 `ca_debt = max(0, ·)` 로 이미 막는다 | 강제전환 확률 > 0 일 때만 limit |
| 잔여 주계약 ≤ 0 | 상각표 없음 | Day-1 차이 — 입력이 서로 안 맞는 자리 (F-05) | limit |
| 비분리형 BW + 매도청구 | 콜 있는 격자 > 없는 격자 (매도청구권 −1.02, 조합시험 random BW#237) | 격자가 «신주인수권을 이미 행사했는가» 를 상태로 갖지 않는다. 자식 노드의 콜은 신주인수권이 살아 있다고 보고 정해지는데(사채 87 을 100 에 사서 신주인수권 38 을 20 으로 누름), 부모에서 투자자가 먼저 행사해 버리면 그 콜은 사채만 비싸게 사는 셈이 된다. 두 상태 격자로 고치는 것은 산식 변경 — 별도 승인 대상 (P2) | BW 비분리 + 콜이면 limit |
| 주주간계약 상호소멸의 우선순위 | 콜 우선이 풋을 **올릴** 수도 있다 (55.58 → 73.04) | 두 격자는 서로 다른 게임이다. 상대의 소멸이 내 계속보유 값을 바꿔 «행사할까» 판단 자체가 달라진다 | 단조성 검사에서 제외, `[20]` 은 동률이 값에 닿는지만 본다 |
