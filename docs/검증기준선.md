### 손계산 시험의 독립성

`tests/손계산대조.py` 의 17 갈래 중 **엔진 출력을 기대값으로 쓰는 것은 없다.** 기대값은
계약에서 손으로 센 값이거나(이표 일정, 즉시행사 금액, 결정표), 항등식이거나(배분 합계
100, 분포 합 1, 행사확률 합 1), 옛 코드를 그대로 옮긴 사슬이다([16] 동등성 — 기대값이
옛 코드라 새 함수를 고쳤다고 갱신하면 안 된다). 나머지 여섯 시험은 「엔진 = 조서」를
보는 것이라 **둘이 같이 틀리면 통과한다** — 그래서 손계산 시험이 따로 있다.

## 4. 작업지시서와 실제 HEAD 의 차이

지시서는 `af21f4f` 를 기준으로 썼다. HEAD 는 그 위에 세 커밋이 있고 지시서가 「이미
수정됨」이라 적은 항목 중 **둘은 코드에 없다.** 기계적으로 다시 적용하지 않고 여기
적어 둔다.

### 4-1. HEAD 가 지시서보다 앞선 것 (세 커밋)

| 커밋 | 내용 | 지시서와의 관계 |
|---|---|---|
| `6b462f6` | BW 비분리형 매도청구 신주인수권 소멸 · BW 뿌리 강제 보유 · 주주간계약 상호소멸 · 역산 목표 · 배당수익률 · σ=0 | 지시서 §11 P0 1·2 가 **이미 고쳐져 있다.** 회귀 시험 `손계산대조 [10]` 이 잠근다 |
| `5664788` | 복합계약 전체 FVPL 지정이 배분표·상각표에 닿는다 | 지시서 §9.1 「전체 FVTPL」 갈래 |
| `9bd6554` | 노드 판정 공통화 `node_decide()` · 만기 층 분포 · 주주간계약 수식 조서 상호소멸 · 검산 탭 | 지시서 §1.3-7 「리팩터링과 산식 변경 분리」 — 이 커밋은 가치를 안 바꿨다 (전 설정 63줄 diff 0) |

지시서 §11 P0-1·2 는 **재현 → 이미 고쳐짐 → 통과 근거** 로 처리한다. 3단계에서
「고치기 전」 값을 옛 커밋(`af21f4f`)에서 다시 재어 결함 표에 넣는다.

### 4-2. 지시서 §1.2 가 「이미 수정됨」이라 했으나 코드에 없는 것

| 항목 | 확인 |
|---|---|
| **GS + 제3자 지정 콜옵션의 비호환 조합 차단** | **사이드바에만 있다.** `app.py:7337`·`7389` 의 `_gs_blk` 가 GS 이면 평가방법 선택칸을 잠그고 `k_method=0` 으로 되돌린다. 그런데 `validate()`·`derive()`·엔진은 막지 않는다 — `decompose(model="GS", k_method=1)` 을 직접 부르면 **경고 없이 다른 값**(매도청구권 8.9862, 화면 강제값이면 12.2404)을 낸다. 지시서 §6.3 「화면·validate·직접 호출이 다른 결과를 내지 않게」 위반. **4단계 결함 후보 F-01** |
| **B2/B3 화면 제목 및 회계분류 안내 문구** | 화면에 「B2」「B3」 라벨이 없다. 결과 탭이 「전체 가치」「매도청구권 반영」 같은 말로 쓴다. 2단계 스냅샷 시험 대상 |

나머지 다섯(뿌리 즉시행사 · 발행일 기준 지급 · 전 구간 q · K_cap · 조정일 이월)은
코드와 시험에 있다.

같은 종류의 틈이 넷 더 있다 — 화면은 막는데 엔진은 조용히 계산한다.

| 화면이 막는 조합 | 화면 장치 | 엔진 직접 호출 |
|---|---|---|
| GS + 지분·부채 분리 (`k_method=2`) | `_gs_blk` | 계산됨 (매도청구권 9.1886) |
| 전환권 부채 + 조기상환권 미분리 (`p_sep=0`) | `_psok` 체크박스 잠금 | 계산됨 — 다만 `allocate()` 안의 `psep` 가 부채 갈래에서 미분리를 무시하므로 **값은 화면과 같다** |
| GS + BDT (`put_bdt=1`) | `_ok` 체크박스 잠금 | 계산됨 — `put_bdt_on()` 이 TF·자본에서만 참이라 **값은 화면과 같다** |
| 전환권 부채 + BDT | `_ok` | 위와 같다 |

값이 실제로 갈리는 것은 GS + `k_method` 1·2 둘이다. 나머지 셋은 엔진 안쪽 판별
함수가 이미 무시하고 있어 값은 같지만, **경고 없이 설정을 조용히 버린다**는 점은
같다. 4단계에서 `validate()` 에 EXPECTED_BLOCK 을 두고 `derive()` 가 세 경로를
하나로 맞춘다.

### 4-3. 하드 차단은 둘뿐

`st.stop()` 은 네 자리인데 뜻은 둘이다 — **σ ≤ 0** 과 **q 가 [0, 1] 을 벗어난 구간이
있을 때**. 나머지 `validate()` 34 항목은 경고이고 계산은 진행된다. 어느 것을
EXPECTED_BLOCK 으로 올려야 하는지는 2단계 매트릭스가 정한다.

## 5. `derive()` 가 강제하는 호환 제약

이산 분기의 데카르트 곱을 만들 때 **이 제약을 먼저 걸어야** 있을 수 없는 조합을
세지 않는다.

| 상품 | 강제되는 값 |
|---|---|
| 주주간계약 | `mat_mode=1 issuer_call=0 div_mode=0 rfx_mode=0 cpn=0 ytm=0 k_w=0 k_method=0 k_lock=0 p_sep=1 k_sep=1 put_bdt=0 ipo_conv=0 carry=1` |
| 신주인수권부사채 | `mat_mode=1 issuer_call=0 div_mode=0`; 대용납입이면 `bw_detach=0` |
| RCPS 제3자 지정 콜 (`issuer_call=2`) | `k_third=1 k_transfer=0 k_sep=1` |
| RCPS 발행자 상환권 (`issuer_call=1`) | `k_w=1 k_method=0 k_lock=0 k_third=0 k_transfer=0 k_sep=0` |
| RCPS 콜 없음 (`issuer_call=0`) | `k_w=0 k_method=0 k_lock=0 k_third=0 k_transfer=0 k_sep=1` |
| 전환권 자본이 아니면 | `fvpl_on()` 이 거짓 — 전체 FVPL 지정이 배분표를 바꾸지 않는다 |
