# 평가용역 업무용 앱 개편 기준

이 문서는 기존 V2 구조 분리 이후의 제품 설계 기준이다. 현재 구현 완료를 의미하지
않는다. 기능을 채택하거나 유지할 때 효과성·효율성·이용편의성을 함께 판단한다.
적용 대상은 CB·BW·RCPS·주주간계약 평가이며, 개별 계약의 지원 범위를 표시한다.

## 1. 완료할 업무와 품질 기준

| 기준 | 사용자가 얻어야 하는 결과 | 확인 방법 |
|---|---|---|
| 효과성 | 계약조건이 평가 현금흐름·행사조건에 어떻게 반영됐는지 설명하고, 검토자가 입력부터 결과까지 따라갈 수 있음 | 계약 조항 대조, 독립 손계산·기준모형 대조, 조서와 결과의 일치 |
| 효율성 | 전기·동일 계약의 반복 입력, 불필요한 계산, 조서 작성과 검토 대응 시간을 줄임 | 입력 횟수, 엔진 실행 횟수, 처리시간, 최대 메모리, 수작업 수정 횟수 비교 |
| 이용편의성 | 해당 업무에 필요한 항목과 남은 확인사항을 알 수 있고, 코드·내부 필드명을 몰라도 사용 가능 | 평가자가 도움 없이 입력·수정·평가·조서 저장을 완료하는지 관찰 |

기능 수, 설명 분량, 검증 건수 자체를 성과로 삼지 않는다. 메뉴 축소 과정에서
필수 계약조건·입력오류·미지원 권리·중요 가정은 누락하거나 숨기지 않는다.

## 2. 실제 용역 진행 순서

| 단계 | 작업 | 화면에 필요한 정보 | 보존할 산출물 |
|---|---|---|---|
| 업무 설정 | 대상회사·상품·회차·기준일·평가목적·관점 지정 | 평가대상 수량, 금액·통화·단위, 발행 전 회차 포함 여부 | 기본정보 |
| 자료 수집 | 계약서·변경약정·전기 조서·시장자료 취합 | 받은 자료, 누락 자료, 회사 확인사항 | 자료목록·출처 |
| 계약 정리 | 상환·전환·배당·콜 등 실제 조건 확인 | 조항별 조건, 근거 위치, 조정 이력, 모형 지원 여부 | 계약조건표 |
| 평가 준비 | 시장자료와 평가가정 결정 | 기준일 일치, 계약조건과 다른 가정 및 이유 | 입력표·가정표 |
| 평가 실행 | 선택한 방법으로 평가 | 전체가치·필요한 구성요소·주당가치·총액, 적용 단위 | 계산 결과 |
| 검토 | 오류·누락·민감한 가정과 전기 차이 확인 | 이슈별 사실·영향·조치, 검산의 범위와 결과 | 검토메모·변경내역 |
| 조서 작성 | 사용자가 선택한 분석과 근거 출력 | 조서 구성과 용량 예상, 남은 이슈 | Excel 조서·요약·입력파일 |
| 후속 업무 | 검토의견 반영·다음 결산·다른 회차 재평가 | 이전 결과와 구분되는 변경사항, 갱신해야 할 자료 | 평가 버전별 기록 |

회계분개·상각표는 용역 범위에 필요한 경우에만 포함한다. 기초자산·계약조건의
검토가 끝나지 않았는데 결과 숫자만으로 평가가 완료된 것처럼 표시하지 않는다.

## 3. 화면과 입력 원칙

- 기본 화면은 `입력`, `평가 결과`, `조서`로 구성한다. 시장자료·평가가정은 입력 안에서,
  전기 차이·확인사항은 결과 안에서 필요한 수준으로 펼쳐 본다.
- 상품과 계약상 권리의 유무에 맞춰 필요한 입력만 표시한다. 풋이 없다는 사실을
  시작일·종료일에 임의 숫자를 넣는 방식으로 표현하게 하지 않는다.
- 날짜는 실제 날짜로, 비율은 화면에 표시된 % 단위로 입력한다. 내부 소수·개월 환산은
  앱이 처리하고, 환산 기준은 확인할 수 있게 한다.
- 원·백만원, 100 기준·주당·총액을 명확히 구분한다. 결과의 주 표시 단위는 실무에
  쓰는 주당가치·총액으로 하고, 100 기준 값은 상세 내역에 둔다.
- 같은 입력을 여러 화면에서 반복해서 요구하지 않는다. 기존 자료를 복사한 경우
  기초자산가격·금리·변동성·발행수량·권리 변경 등 갱신할 항목을 표시한다.
- 기본 경로에 JSON 편집, 내부 필드명, 개발용 상태코드, 명령어를 노출하지 않는다.
- 경고는 중복을 합치고 `문제 내용 / 평가에 미치는 영향 / 필요한 조치`로 제시한다.
  긴 이론 설명과 계산식은 도움말에서 선택해서 읽는다.
- 미지원 권리는 중요한 이슈로 남긴다. 기능을 켜거나 이름을 기록한 것과 현금흐름에
  실제 반영된 것을 구분한다.

## 4. 기존 기능의 1차 처리안

아래는 현재 코드에서 확인한 기능군의 업무상 배치안이다. 모든 설정 조합의 타당성을
검토 완료했다는 의미는 아니다. 세부 설정·판단 규칙은 기능군별로 추가 대조한다.

| 기존 기능군 | 처리안 | 실무 적용 기준 |
|---|---|---|
| 회사·상품·기준일·회차·관점 | 기본 유지 | 업무 시작 시 한 번 지정 |
| 발행금액·수량·주당가치·단위 | 기본 유지 | 서로 대사되는 값으로 관리 |
| 전환·상환·이자·배당 조건 | 기본 유지 | 해당 계약에 필요한 항목만 노출 |
| 발행자 콜·제3자 콜·의무보유 | 조건부 노출 | 실제 권리가 있을 때만 입력 |
| 정기 리픽싱 | 조건부 노출 | 사건형 조정과 구분하고 지원 방식 표시 |
| IPO 관련 조건 | 조건부 노출·재검토 | 계약상 조건과 발생 시점·가격 가정 구분 |
| 배당가능이익·기간연장·희석 등 | 중요 이슈로 유지 | 지원 여부와 실제 반영범위를 결과에 표시 |
| 금리곡선 입력·변환 | 기본 유지 | 시장자료 입력과 계산·복리 기준 연결 |
| 주가·피어·변동성 산출 | 선택 실행 | 수집·재산정 버튼으로 실행하고 자료 재사용 |
| 부트스트래핑 상세·일별 원시자료 | 상세 보기 | 기본 화면의 장문·대형 표를 줄임 |
| 기초자산가격 역산 | 선택 실행·재검토 | 역산 목적·기준 가격·가정부터 확인 |
| 신용스프레드 역산 | 선택 실행·재검토 | 발행가격 차이를 단일 원인으로 단정하지 않음 |
| 전체가치·주당가치·총액 | 기본 유지 | 결과의 첫 화면에 제시 |
| 구성요소 분해 | 목적별 표시·재검토 | 전체가치·분해 차액·회계 인식액 구분 |
| TF·GS 비교 | 선택 실행 | 적용 모형의 결과와 추가 비교를 구분 |
| 콜 평가방법 비교 | 선택 실행·재검토 | 계약 대상·의무보유·평가 단위를 먼저 확인 |
| 풋·콜 행사 우선순위 비교 | 조건부 선택 실행 | 중복 행사 가능성과 계약상 우선순위가 관련될 때 |
| 금리·주가·변동성 민감도 | 선택 실행 | 선택 변수·범위만 계산하고 결과 재사용 |
| IPO 시점별 시나리오 | 선택 실행 | 기본 평가와 별개 가정임을 표시 |
| BDT 적용 판단 | 자동 결론 재검토 | 임계값·근거·적용범위 확인 전 판단 참고자료로 취급 |
| 회계분류·내재파생 분리 판단 | 자동 결론 재검토 | 확인된 사실, 판정 규칙, 전문가 판단 구분 |
| 분개·거래원가 배분·상각표 | 용역 범위에 따라 선택 | 공정가치만 필요한 업무에는 기본 출력하지 않음 |
| 입력 누락·단위·날짜·곡선 오류 | 상시 자동 확인 | 평가에 영향을 주는 오류는 실행 전에 표시 |
| 위험중립확률·합계·현금흐름 대사 | 상시 자동 검산 | 기존 계산 결과를 재사용해 불필요한 재평가 방지 |
| 상세 노드·의사결정 분포 | 상세 보기 | 검토나 원인 분석에 필요할 때 조회 |
| 극단값·분기전수·개발용 테스트 | 개발·검증 환경으로 분리 | 기본 업무 화면과 기본 조서에서 제외 |
| '모두 적합' 등 종합 표시 | 표현 변경 | 무엇을 검사했고 무엇은 검사하지 않았는지 한정 |
| 장문 이론·문답·비유적 표현 | 도움말 이동·문구 교체 | 사실·영향·조치를 짧은 업무 문장으로 작성 |
| 검토결론 자동 문안 | 근거 점검 후 선택 출력 | 수행하지 않은 검토나 확정하지 않은 결론을 쓰지 않음 |
| 값·수식 조서 | 기본 유지·선택 생성 | 결과 일치 여부와 수식 재계산 범위 표시 |
| 전기 불러오기·입력 변경 비교 | 기본 유지·확장 | 새 기준일 자료를 덮어쓸 때 변경 내용을 보존 |
| 다회차 복사·기준일별 합산 | 후속 구현 | 회차별 실제 발행일·수량과 권리조건 분리 |

## 5. 자동 판단과 검증의 신뢰도

자동 검증을 세 층으로 구분한다. 어느 한 층의 통과를 전체 평가의 적정성 결론으로
표시하지 않는다.

| 구분 | 확인 내용 | 앱의 역할 |
|---|---|---|
| 입력·산술 검증 | 날짜·단위·확률·합계·조서 대사 | 명확한 규칙으로 자동 확인 |
| 금융모형 검증 | 현금흐름·행사조건·할인·만기 지급·구성요소 분해 | 독립 기준값과 대조하고 검증 범위·미검증 조합 표시 |
| 계약·회계·평가 판단 | 분류·분리·모형 선택·계약 해석·중요성 | 사실·근거·계산 영향 제시, 판단 근거 기록 |

판단 규칙을 유지하려면 근거 자료의 위치, 적용조건, 제외조건, 임계값의 출처,
판단이 바뀌는 경계 사례, 독립적인 반례 검토를 남긴다. 코드가 자체 기준을 지킨다는
시험만으로 그 기준 자체가 적절하다고 결론 내리지 않는다.

BDT의 5%p·0.2·70% 기준과 자동전환 RCPS 분해 등은 우선 재검토 대상이다.
수치 기준의 타당성 검토 전에는 문구를 단정적으로 바꾸거나 '검증 완료'를 표시하지 않는다.

## 6. 계산 효율과 반복 업무

- 평가 실행, 추가 분석, 조서 생성을 분리한다. 탭 이동이나 설명 조회가 재평가를
  유발하지 않게 한다. 조서를 열기만 했는데 무거운 추가 분석이 실행되지 않게 한다.
- 계산 입력이 같은 경우 결과를 재사용한다. 메모·출처만 바뀌면 기록을 갱신하되
  수치 계산은 다시 하지 않는다. 계산 가정이 바뀌면 이전 결과임을 분명히 표시한다.
- 입력을 묶어서 저장·평가한다. 숫자 하나를 입력할 때마다 모든 트리를 재계산하지 않는다.
- 추가 분석의 변수·범위·예상 작업량을 보여 주고 요청한 분석만 실행한다.
- 큰 수식 조서는 예상 크기와 생성 단계를 표시한다. 편의를 위해 계산방법을 몰래
  바꾸거나, 값 조서와 수식 조서의 차이를 누락하지 않는다.
- 전기·동일 회사·동일 계약을 복사하되 날짜가 지난 시장자료를 새 자료처럼 사용하지 않는다.
- 앱을 통해 생성한 입력파일을 대화형 작업에서도 그대로 사용하고, 반대 방향도 지원한다.

성능 개선은 같은 환경·입력·노드 수·방법에서 비교한다. 아직 측정하지 않은 속도
향상을 주장하지 않는다. 데이터 부족을 성능 설정으로 덮거나 정확도를 낮춰 빠르게
보이게 하지 않는다. 근사법을 선택하면 방법과 결과 영향이 표시되어야 한다.

## 7. 조서와 검토 대응

기본 조서는 업무 개요, 결과 요약, 계약조건, 적용 가정·근거, 시장자료, 필요한 계산내역,
핵심 검산, 미해결 사항으로 구성한다. 상세 트리·민감도·회계처리·개발용 분석은
필요성과 용역 범위에 따라 분리한다. 확인되지 않은 계약조건이나 미검토 판단이
조서 문안에서 검토 완료로 바뀌지 않게 한다.

보고서에 옮길 금액·단위·기준일·대상 회차를 일관되게 표시한다. 회사나 검토자가
질문하면 어느 계약 조항과 어떤 가정을 사용했는지 해당 기록을 찾을 수 있어야 한다.
자료 수정 후에는 결과·조서·입력파일이 같은 평가 버전을 가리켜야 한다.

## 8. 업무 적용 전 확인할 시나리오

| 시나리오 | 통과 기준 |
|---|---|
| 신규 계약 평가 | 자료 누락과 미지원 조건을 식별하고 입력부터 조서까지 연결 |
| 전기 평가 갱신 | 유지한 계약조건과 변경된 시장자료·가정을 구분하고 결과 비교 |
| 검토의견 반영 | 관련 입력만 수정하며 변경 근거·전후 결과와 조서가 일치 |
| 다회차 계약 | 미발행 회차가 기말 평가에 섞이지 않고 회차별 수량·금액이 대사 |
| 복잡한 RCPS | 지원하지 않는 권리를 계산한 것처럼 표시하지 않고 필요한 별도 분석을 명시 |
| 산출물 대사 | 화면·값 조서·지원 범위 내 수식 조서의 평가방법과 결과가 일치 |
| 이용편의성 | 평가자가 JSON·내부 코드명을 입력하지 않고 주요 업무를 수행 |
| 성능 | 탭 이동·설명 조회·메모 수정 시 엔진 재실행 0회. 선택하지 않은 추가 분석 실행 0회 |

위 항목은 완료 기준이며 현재 통과했다는 보고가 아니다. 테스트 건수보다 실제 업무
시나리오의 성공 여부와 남은 위험을 근거로 업무 적용 여부를 판단한다.

## 9. 구현 우선순위와 현재 차이

1. 기능·화면·자동 판단 목록을 정리하고, 유지·선택 실행·업무 화면 제외·재검토 대상을 확정한다.
2. 자동 판단 규칙과 문구를 함께 검토한다. 특히 근거보다 강한 결론을 내리는 문안을 수정한다.
3. 기본 업무 화면을 단순화하고 원·%·날짜 입력, 반복자료 재사용, 오류 안내를 개선한다.
4. 계산·추가 분석·조서를 분리하고 실제 실행시간과 메모리를 측정한다.
5. 미지원 금융모형을 계약 사례별로 구현·검증한다. 업무 기능과 검증 완료 범위를 함께 공개한다.
