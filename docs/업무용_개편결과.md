# 업무용 화면·조서 개편 결과

작업일: 2026-09-28. 대상 브랜치: `codex/valuation-v2-workflow`.
이 문서는 로컬 구현과 검증 결과다. GitHub 업로드·운영 앱 반영을 완료했다는 의미는 아니다.

## 사용자가 체감하는 변경

| 항목 | 종전 | 이번 구현 |
|---|---|---|
| 기본 진입점 | 상세 기능·설정 중심 화면 | `app.py`에서 입력 / 평가 결과 / 조서 3개 탭 |
| 계약 입력 | 소수 비율·발행 후 개월·상세 설정 JSON | %·원·실제 날짜, 권리 유무에 따라 필요한 항목 표시 |
| 결과 | 구성요소·진단·상세 설명 혼재 | 총액·RCPS 주당가치 우선, 구성요소는 펼쳐 보기 |
| 검증 문구 | 장문 경고·자동 판단·추가 계산 혼재 | 산술 검산과 평가자 확인사항 분리, 사실·영향·조치 표시 |
| 재계산 | 화면 실행과 여러 분석이 연결 | 평가 버튼으로 실행. 동일 입력은 결과 재사용 |
| 메모·출처 수정 | 결과 삭제 후 재평가 | 수치 재사용, 최신 근거·메모로 기록 갱신 |
| 수치 수정 | 결과 무효화 | 변경 전 결과임을 표시하고 재평가 전 조서 출력 차단 |
| 민감도 | 여러 변수의 분석이 기본 화면과 연결 | 선택한 변수의 감소·증가 2개 조건만 버튼으로 계산 |
| 기본 조서 | 큰 격자·회계처리·판단 문안 포함 | 결과·계약·시장자료·가정·검산·확인사항·출처 기록 |
| 상세 조서 | 기본 업무와 혼재 | 값·수식 조서를 명시적으로 선택하여 생성 |
| 반복 업무 | 기존 입력 재사용 | 전기 입력 복사·변경내역 비교·시장자료 기준일 차이 표시 |

기존 상세 화면은 `legacy_app.py`로 보존했다. 이전 기능을 새 기본 화면에서
모두 동일하게 재구현한 것은 아니다. 가격·변동성 자료 수집, 역산, 회계분개,
모형 간 전수 비교 등은 종전 상세 화면·전용 도구와 구분한다.

## 계산과 기록의 일치

- 기존 `valuation/legacy.py`의 금융 계산식은 이번 업무 화면 개편에서 수정하지 않았다.
- 계산 재사용 키는 적용되는 모든 엔진 입력과 계산 코드 해시를 포함한다.
  임의로 ‘영향 없을 것’이라고 추정한 입력을 키에서 제외하지 않는다.
- 건명·출처·검토메모·가정 근거 등 기록만 바뀌면 기존 수치와 원래 계산시각을 유지한다.
  입력 식별값과 기록 갱신시각은 새 기록에 맞게 바꾼다.
- 원본 계약조건과 별도 가정은 분리 보존한다. 민감도 분석도 기본 계약을 수정하지 않는다.
- 화면에 표시한 날짜를 수정하지 않은 경우 기존의 소수 개월 값을 그대로 보존한다.
  실제 발행일을 바꾸면 행사일은 실제 날짜를 기준으로 다시 환산한다.
- 행사일의 역전, 잘못된 행사금액표, 입력자료형 오류를 정상 입력으로 조용히 바꾸지 않는다.
- 기본 조서는 저장된 결과와 직접 대사한다. 출처 텍스트가 `=`로 시작해도 Excel 수식으로 실행되지 않는다.

## 자동 판단의 처리

| 규칙·표현 | 이번 처리 | 남은 검토 |
|---|---|---|
| ‘모두 적합’ 종합 결론 | 기본 화면·조서에서 사용하지 않음 | 계약·모형·회계 판단은 별도 검토 |
| 위험중립확률 | 기존 계산 결과에서 0 < 확률 < 1 확인 | 모형 자체의 타당성과 구분 |
| 구성요소 합계 | 동일 실행 결과의 산술 대사로 표시 | 독립 계산과의 대조를 대신하지 않음 |
| BDT 5%p·0.2·70% 임계값 | 기본 경로에서 적합·부적합 결론에 사용하지 않음 | 임계값의 근거·적용범위 미검증 |
| 날짜만 보고 의무보유 존재 추정 | 제거. 입력한 제한 조건과 계약 대조를 요청 | 실제 계약 조항 확인 |
| 신용스프레드 1% 미만이면 자료 오류 추정 | 제거. 음수 선도 스프레드는 관찰 사실만 표시 | 곡선 대상·날짜·복리 기준 대조 |
| ‘BDT 부채요소가 작으므로 옵션가치 오류’ | 기본 자동 결론에서 제외 | 서로 다른 모형·분해 방식의 비교 기준 검토 |
| 자동전환 RCPS 주계약·전환권 차액 | 참고값으로 표시 | 회계 인식액·분류 결론과 별도로 판단 |
| 미지원 권리 등록 | 직접 모형화되지 않음을 계속 표시 | 배당가능이익·배당연장·사건형 조정·희석·청산배분 추가 개발 |
| 회계분개·분리 판단 자동 문안 | 기본 조서에서 제외. 상세 조서도 해당 시트 제외 | 새 업무 화면의 회계처리 기능은 후속 범위 |

상세 수식 조서에서 제거된 시트를 참조하는 수식이 남으면 출력을 중단한다.
상세 조서의 일부 계산 설명은 기존 형식을 유지한다. 생성한 모든 파일의 Excel 전체
재계산과 모든 모형 조합의 타당성을 완료했다고 주장하지 않는다.

## 업무 시나리오 검증

`tests/test_v2_workflow.py`, `tests/test_business_workflow.py`로 다음을 검사했다.
최종 실행 결과는 **71개 통과, 12.61초**다.

- CB·BW·RCPS·주주간계약 화면 시작, 상품에 맞는 권리 표시, 3개 기본 탭.
- 신규 평가의 주당가치·금리 미입력 상태 유지 및 평가 실행 차단.
- % 단위 입력과 계산용 소수 환산, 날짜 표시·저장 시 기존 소수 개월 보존.
- 계약 원본을 유지하는 가정 변경과 미지원 권리의 시나리오 연결.
- 화면 재표시·출처 및 메모 수정·동일 입력 재평가·기본 조서 생성에서 추가 격자 계산 0회.
- 계산 입력 변경 시 이전 결과 식별·조서 생성 차단, 잘못된 행사기간 저장 차단.
- 전기 기준일 변경 후 이전 시장자료 기준일을 확인사항에 유지.
- 민감도에서 요청한 2개 조건만 계산, 기본 입력·결과 불변.
- 화면 결과·기본 Excel 조서의 총액·주당가치·원금 100 기준 금액 대사.
- 네 상품의 상세 값·수식 조서 생성, 자동 판단 시트 제외, 입력 기록·해시 보존.
- CLI와 앱의 공통 서비스 결과 일치.

기존 오라클, 기능목록(`--strict`), 분기전수도 실행했다. 분기전수는 374개 모두 통과했다.
독립 오라클이 연결된 범위는 기능목록상 374개 분기 중 126개다.
따라서 분기전수 374개 통과를 374개 전부의 독립 검증으로 표현하지 않는다.

이전 1차 개편의 8개 검증 묶음 결과와 아직 끝내지 않은 전수시험은
`V2_검증기록.md`에 유지했다. 이번에는 금융 계산식을 바꾸지 않았으며,
새 UI·서비스·조서 경로의 구체적인 위험을 중심으로 시험했다.

## 업무 적용 전에 남은 사항

1. 실제 계약서와 회사 자료를 사용한 평가자 사용성 확인 및 결과 독립 검토.
2. 상세 수식 조서의 모든 지원 조합에 대한 Excel 재계산·화면 검토.
3. 미지원 RCPS 권리의 직접 모형화 및 실제 계약 사례별 검증.
4. 다회차 평가대상 관리·합산과 신규 회계처리 화면.
5. GitHub 브랜치 업로드 및 운영 앱 반영. 앞선 자동 승인 검토에서 업로드에 대한
   명시적 승인이 없다는 이유로 거절되어 로컬 작업까지만 수행했다.

실행시간·메모리·호출 횟수는 `업무화면_성능측정.json`에 입력과 함께 기록했다.
측정치는 합성 RCPS 60구간, 동일 저장 결과에 대한 기본·상세 조서 비교다.
Python 메모리 할당 추적을 켠 단일 실행이며 전체 프로세스 메모리나 반복 측정 통계가 아니다.

| 작업 | 시간(초) | 주가 격자 호출 | 최대 Python 할당(MiB) | ZIP 크기(바이트) |
|---|---:|---:|---:|---:|
| 기본 평가 | 2.308 | 4 | 6.537 | 해당 없음 |
| 메모 갱신 | 0.016 | 0 | 0.590 | 해당 없음 |
| 기본 조서 | 0.616 | 0 | 7.189 | 25,700 |
| 상세 값 조서 | 17.038 | 9 | 25.550 | 152,928 |

기본·상세 조서의 포함 범위가 다르다. 이 수치를 금융 계산식 자체의 속도 향상률로
해석하지 않는다. 기본 경로에서 선택하지 않은 상세 작업을 실행하지 않는 효과다.
