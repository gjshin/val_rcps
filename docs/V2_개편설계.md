# V2 — 대화형 평가와 앱을 함께 사용하는 작업공간

이 문서는 1차 개편 당시의 설계 기록이다. 이후 구현한 통합 화면·판단 근거·계약조건 분석·
회차 취합·가치변동 대사 및 현재 지원 범위는 [업무 개편 기록](근거연결_업무개편.md)을 확인한다.
아래의 ‘후속 범위’와 ‘현재 미구현’ 표현은 1차 개편 시점을 기준으로 한다.

## 목표

계약서 검토로 작성한 입력안을 앱에서 확인·수정하고, 같은 입력파일과 같은 계산부로
평가·검토조서를 생성한다. 계약의 사실, 시장자료, 평가가정, 계산 결과, 회계판단을
구분한다. 전기 금액에 맞추기 위한 임의 보정은 하지 않는다.

후속 개편의 우선 기준은 [평가용역 업무용 개편 기준](업무용_개편기준.md)이다.
효과성·효율성·이용편의성을 기준으로 기존 기능과 자동 판단을 재검토하고,
기본 화면은 입력·평가 결과·조서 중심으로 줄인다. 아래의 5개 탭·상세 JSON 편집은
현재 시제품의 구현 상태이며 최종 업무 화면의 목표가 아니다.

## 이번 구현 범위

| 구분 | 구현 |
|---|---|
| 공통 계산부 | 기존 `app.py`의 화면 이전 계산·조서 함수를 `valuation/legacy.py`로 이동. Streamlit 의존성을 제거 |
| 공통 입력 | `valuation/case.py`: 계약·시장·방법·근거·평가가정·추가권리 구분, 버전 관리 |
| 공통 실행 | `valuation/service.py`: 입력검증, 기존 계산부 호출, 실행 스냅샷, 조서 묶음 |
| 새 화면 | `workspace_app.py`: 계약조건 / 시장자료·방법 / 가정·추가권리 / 평가·조서 / 전기 비교 |
| 대화형 작업용 도구 | `tools/run_case.py`: 기존 시나리오 가져오기, 검토, 평가·출력 |
| 기존 경로 | 상세 앱·변동성 전용 앱·기존 평가 도구도 분리된 계산부 사용 |
| 전기 비교 | 계약·시장자료·가정·출처·추가권리의 변경내역. 가치변동 요인별 재평가 브리지는 후속 범위 |

이번 변경은 **작업 흐름 개편과 계산부 분리**다. 계산식을 검증 없이 새로 쓰는 작업은
포함하지 않는다. `valuation/legacy.py`에는 기존 회계·조서 함수도 남아 있으며,
완전히 분리된 새 RCPS 계산모형이라고 부를 수 없다.

## 사용 흐름

1. 대화형 작업에서 계약서와 시장자료를 검토하고 V2 입력안을 작성한다.
2. 앱에서 계약조건과 적용 가정, 금리곡선, 출처를 확인한다.
3. 추가권리의 미해결·제외·시나리오 처리와 그 근거를 기록한다.
4. 입력검증을 통과한 경우 검토용 계산을 실행한다.
5. 결과·계약과 가정 대조표·추가권리 목록·입력파일·실행기록을 함께 내려받는다.
6. 전기 평가파일을 넣으면 입력·근거의 변경내역을 함께 저장한다.

PDF 자동 해석 또는 LLM 호출 기능이 앱 자체에 내장된 것은 아니다. 대화형 작업에서
만든 구조화 입력파일과 앱이 연결되는 방식이다. 기존 평면 시나리오도 가져올 수 있다.
새 화면의 '새 평가 만들기'로 빈 계약·시장 입력안도 만들 수 있다. 방법 기본값은
TF·투자자 관점·1개월이며 화면에 표시된다. 필수 가격·금리·날짜는 비워 둔다.
세부 조건은 상세 설정 영역 또는 기존 상세 앱을 이용한다.

## 계약조건과 가정의 구분

예를 들어 계약의 상환청구 시작이 36개월이고 평가상 회수 가능 예상시점이 72개월이면:

- `contract.p_s = 36`: 계약조건을 보존한다.
- `assumptions`: `field=p_s`, `value=72`, 변경 근거를 기록한다.
- `additional_rights`: 배당가능이익 제약을 `scenario`로 표시하고 `p_s` 가정을 연결한다.
- 조서에는 원본 36, 적용값 72, 변경 근거, 출처를 함께 기록한다.

**시작일 변경은 배당가능이익 제약을 정확하게 평가하는 모형이 아니다.** 부분상환·
미상환금 이월·배당과 상환재원의 경쟁을 표현하지 못하는 시나리오 근사라는 점이
검토사항에 남는다. `scenario` 지정만으로 계산이 추가되는 것도 아니다.

## V2 입력파일

| 영역 | 내용 |
|---|---|
| `schema` | `valuation-case/2` |
| `name` | 평가 건명 |
| `contract` | 확인된 계약조건. 기존 계산부의 필드명을 사용 |
| `market` | 주가·변동성·금리곡선·신용자료 |
| `method` | 평가기준일·관점·계산방법·격자 등 |
| `sources` | 필드별 출처·기준일·산출근거 |
| `assumptions` | 필드·적용값·변경 근거. 계약조건을 덮어쓰지 않음 |
| `additional_rights` | 추가권리의 조항·처리·근거·연결 가정 |
| `imported_defaults` | 기존 시나리오에 없어 보충된 기본값 목록 |
| `notes` | 기타 메모 |

기존 시나리오 가져오기는 종전 기본값을 명시적으로 채우고 그 목록을 남긴다.
**가져오기 성공은 계약검토 완료를 뜻하지 않는다.** 필수 시장값·날짜·단위와
기본값 보충 목록을 검토한다. 잘못된 필드명은 조용히 버리지 않는다.

## 실행

```bash
python -m streamlit run workspace_app.py

# 기존 시나리오 → V2 파일 (가상 예시 경로)
python tools/run_case.py /outside-repo/old.json --import-legacy --out /outside-repo/case.json

# 입력 검토: 오류가 있으면 종료코드 1
python tools/run_case.py /outside-repo/case.json --inspect

# 검토용 값 조서 묶음
python tools/run_case.py /outside-repo/case.json --out /outside-repo/review.zip

# 같은 모형의 수식 조서와 전기 변경내역
python tools/run_case.py /outside-repo/case.json --formula \
  --previous /outside-repo/prior.json --out /outside-repo/review_formula.zip
```

고객 계약·시장자료·평가결과는 저장소에 넣지 않는다. ZIP은 case.json, result.json,
applied_inputs.json, review.md, 검토기록을 추가한 Excel, 파일별 SHA256 목록을 담는다.
전기 파일을 지정하면 changes.json도 포함된다. 수식 출력은 값 출력과 별도로 생성한다.

## 계산·출력 기준

- 입력 누락, 잘못된 날짜·숫자·선택값·금리곡선, 지원하지 않는 설정 조합은 오류로 처리한다.
- 계산 중 위험중립확률이 범위를 벗어나면 결과를 내보내지 않는다.
- 사용자 입력을 기존 엔진이 상품별로 정규화한 내용은 실행기록에 남긴다.
- 계산용 Terms, 결과, 입력파일을 하나의 실행 스냅샷으로 묶는다. 입력을 저장하면 화면의
  이전 결과와 조서가 무효화된다.
- 수식으로 표현할 수 없는 상태확장 리픽싱을 다른 방법으로 자동 변경하지 않는다.
- 수식 조서 생성 시 전체 Excel 재계산을 자동 수행하지 않는다. 이를 출력물에 명시한다.
- 자동전환 RCPS의 주계약·전환권 분해는 기존 모형의 참고값으로 표시한다.
- V2 결과는 항상 검토용이다. 자동 회계분류 확정이나 최종 평가 서명 기능은 없다.
- 구간 한도: 일반 격자 1,200, 상태확장 리픽싱 100. 성능·상태공간 설계 전 임시 한도다.

## 실제 금융모형 개편 — 다음 구현 순서

| 순서 | 개발 항목 | 구현 전 확정할 사항 | 완료 기준 |
|---|---|---|---|
| 1 | 날짜·사건 일정과 격자 | 초일·말일, 실제 일수, 행사·지급시차, 정확한 7일과 단순 평균 간격의 구분 | 휴일·윤년·만기 잔여구간·전환/상환 경계의 독립 검산 |
| 2 | 만기 지급조건과 구성요소 분석 | 자동전환 시 전체 지급조건, 전환권 제거 시 비교계약 정의, 회계상 분해 목적 | 계약별 단순 한계값 검산 및 전기 원본 모형과 차이 설명 |
| 3 | 배당가능이익·누적배당 | 재원 전망, 실제 지급이력, 청구순위, 부분상환·미상환 이월·기간연장 정책 | 현금·주식수·미상환 원금·미지급 배당 잔액 보존 및 손계산 사례 |
| 4 | 사건형 전환가 조정 | 저가발행 가중평균식, IPO/M&A 가격, 연속 조정, 절사·하한 | 정기 리픽싱과 구분된 개별 계약 사례 검산 |
| 5 | 자본구조·다회차 | 기존 종류주식, 청산순위·참가권, 전환 여부별 분모·청구권 소멸 | 배분총액 보존, 중복 차감·희석 방지, 회차별 평가·합산 |
| 6 | 조건부 권리·전기 가치변동 분석 | 사건·의무자·회수경로·상호소멸, 요인별 변경 순서 | 중복계상 방지와 전체 증감 대사 |
| 7 | 모듈 추가 분리·화면 완성 | 계약 정의 / 일정 / TF·GS / 회계 / Excel 각각의 인터페이스 | legacy.py 축소, 모든 사용 경로의 결과 일치 |

배당가능이익 제약·누적배당 연장·청산배분·실제 희석은 현재 직접 계산되지 않는다.
7일 격자도 아직 미구현이다. V2는 기존 0.25개월 하한보다 짧은 간격을 명시적으로
거절하며, 결과에 실제 평균 일수를 표시한다. 기존 상세 앱의 주 단위 UI 문제는
이관된 계산부의 남은 결함으로 추적한다.

## 검증

기존 손계산·독립 오라클의 기대값은 변경하지 않았다. 코드가 이동했으므로 기존
검증 도구가 계산부의 새 파일을 읽도록 경로와 소스 위치만 변경했다.

```bash
python -m pytest -q tests/test_v2_workflow.py
python tests/run_all.py --quick
python tests/run_all.py
```

새 시험은 자동전환 단순 한계값, 계약과 가정 보존, 미지원 권리 표시 거절,
잘못된 입력 거절, 조서 근거·해시, 텍스트의 Excel 수식 오인 방지, CLI·서비스 일치,
Streamlit 독립 import, 실제 화면의 계산과 수정 후 결과 무효화를 포함한다.
