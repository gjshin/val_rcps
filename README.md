# 전환사채 · 신주인수권부사채 · 상환전환우선주 · 주주간계약 평가

이항격자로 **전환사채(CB)** · **신주인수권부사채(BW)** · **상환전환우선주(RCPS)** ·
**주주간계약(SHA)** 을 평가하고 조서를 엑셀로 내보내는 스트림릿 앱이다. 사이드바
**모형 → 상품** 에서 고른다. 격자·이자율·변동성·조서 기계는 하나를 같이 쓰고,
계약의 성격이 다른 곳만 갈라진다.

```
pip install -r requirements.txt
streamlit run app.py
```

## 무엇을 하나

- 계약조건을 넣으면 옵션을 **순차 차감**으로 하나씩 분리한다
- TF와 GS 두 모형을 나란히 계산해 비교한다
- 리픽싱은 상태확장(정확) 또는 근사 세 가지 중에서 고른다
- 주가를 받아 변동성을, 만기수익률을 받아 선도이자율을 산출한다.
  비상장이면 **발행가로 주가를 역산**하거나 피어 변동성을 쓴다
- 조기상환권을 BDT 금리격자로 잴 수 있다 (금리변동성도 시계열에서 산출)
- 계약 조항에서 **내재파생 분리 여부와 평가방법을 판정**한다
- 기업회계기준서 제1032호 문단 31에 따라 최초 인식 배분과 분개를 만들고,
  거래원가를 요소별로 배분하며(문단 38), 결산 평가에서는 **기말 재평가**·
  **당기 이자비용**·**전환/상환 시 분개**(문단 AG32·AG33·AG34)까지 낸다
- 상환가액은 복리·**단리** 둘 다 — 복리 횟수 칸에 0 을 넣으면 단리다
- RCPS 의 **IPO 조항** — 상장 시 강제전환과 공모가 연동 전환가격 조정 (책 [사례 5-5]).
  상장 성공은 그 노드의 주가가 최소공모가격을 넘는지로 판정하므로 상장 확률을 따로
  넣지 않는다. 상장 시점 가정을 바꾼 표를 함께 낸다
- BW 는 **행사대금 납입 방식**(현금납입 · 사채 대용납입)과 **신주인수권증권의
  분리 여부**를 받는다. 현금납입이면 사채와 신주인수권을 따로 재어 더하고,
  비분리형이면 사채가 소멸할 때 미행사 신주인수권이 함께 사라지는 것까지
  격자에서 푼다 — 자세한 것은 [`docs/입력안내_BW.md`](docs/입력안내_BW.md)
- **주주간계약**은 투자자 풋(보장수익률 행사금액)과 최대주주 콜을 지분가치 격자에서
  각각 미국형으로 재고, 적격상장(Q-IPO) 성공 노드에서 소멸시킨다. 발행회사·최대주주·
  투자자 **세 관점**의 인식액과 분개를 함께 낸다 — 발행회사가 풋 의무자면 옵션
  공정가치가 아니라 상환금액의 현재가치를 **총액**으로 싣는다 (1032 문단 23).
  자세한 것은 [`docs/입력안내_주주간계약.md`](docs/입력안내_주주간계약.md)
- 조서를 **값** 또는 **수식** 형태로 내보낸다

## 순차 차감

```
CB       B0 옵션 없는 사채 → B1 +조기상환청구권 → B2 +전환권     → B3 −매도청구권
BW 대용  같은 길 — 사채를 권면액만큼 납입에 갈음하므로 전환사채와 수학적으로 같다
BW 현금  B0 옵션 없는 사채 → B1 +조기상환청구권 → B2 +신주인수권 → B3 −매도청구권
                            (행사해도 사채가 남으므로 B2 − B1 이 신주인수권이다)
RCPS     B0 우선주부채     → B1 +상환청구권     → B2 +전환권     → B3 −발행자 상환권
                                                  (존속기간 만료 시 자동전환 포함)
SHA      순차 차감이 없다 — 사채가 없고, 지분에 붙은 풋과 콜을 **따로** 잰다
```

옵션은 서로 대체 관계라 따로 재어 더하면 총액이 부풀려진다. 하나씩 얹으며 차액을
보면 합계가 항상 맞는다.

## CB 와 RCPS 의 차이

계산은 같고 **계약의 성격**이 다르다.

| | CB | RCPS |
|---|---|---|
| 기준 금액 | 액면 100 | 1주 발행가 100 |
| 정기 지급 | 표면이자 — 채무 | 우선배당 — **상환가액 가산** 또는 **발행자 재량** (1032 AG37) |
| 만기 | 현금 상환 | **보통주 자동전환** 또는 상환 (스위치) |
| 회사 쪽 콜 | 매도청구권 — 제3자 지정·한도 %·의무보유·세 평가방법 | **세 갈래** — 없음 / 발행자 상환권 / 제3자 지정 매도청구권 |
| 그 권리를 재는 자리 | 전체 격자 (유무가치비교) | 발행자 상환권은 **부채 격자** (1032 문단 31), 제3자 지정 콜은 **전체 격자** |
| 콜의 회계 | 제3자 지정이면 별도 금융상품 (1109 4.3.1) | 발행자 상환권은 복합내재파생에 묶고, 제3자 지정 콜은 **파생상품자산으로 분리** |
| 투자자 상환권이 없으면 | 그래도 부채 | **자본 가능성** (1032 AG25) — 앱이 경고한다. 배당 재량·조건부결제·교부 주식 수를 함께 보아야 확정된다 |
| 발행회사 | 상장사가 많음 | 대부분 비상장 → 발행가 역산 |

계약서를 어느 칸에 넣는지는 [`docs/입력안내_RCPS.md`](docs/입력안내_RCPS.md) 에
차바이오텍 계약을 예로 표로 적어 두었고, 시나리오 파일 하나로 불러올 수도 있다
([`시나리오/`](시나리오)).

자세한 근거와 결정 기록은 [`docs/RCPS_설계.md`](docs/RCPS_설계.md) 에 있고,
실제 발행 사례로 맞춰 본 기록은 [`docs/사례_차바이오텍_RCPS.md`](docs/사례_차바이오텍_RCPS.md) 에 있다 — 공시된 계약을
입력으로 옮기는 법과, 회사가 인식한 금액과 어디까지 맞고 어디서 갈라지는지를 적었다.

반대편 계약도 하나 두었다. [`docs/사례_대신증권_RCPS.md`](docs/사례_대신증권_RCPS.md) 는
**투자자 상환청구권이 없고 발행회사만 상환권을 가진** 2025년 발행 건이다. 앱이 내는
1032 AG25 「자본」 경고가 회사가 실제로 한 회계처리와 맞는지를 확인한 기록이다.

## 조서 두 형식

| | 값 조서 | 수식 조서 |
|---|---|---|
| 성격 | 계산 결과 스냅샷 | 엑셀에서 다시 계산됨 |
| 용도 | 제출용 | 검토·실험용 |
| 상태확장 | 가능 | 경로가중치로 대체 |

트리 하나가 시트 하나이고, 모든 시트의 머리 17행이 같은 형태다. 수식 조서의 **가정**
시트에서 노란 셀을 바꾸면 전체가 다시 계산된다. 흰 셀 가운데 평가방법·신용위험 처리·
BDT 관련 줄은 **앱에서 고른 값**이라 엑셀에서 바꿔도 트리가 따라오지 않는다.

## 시험

조서나 격자를 고쳤으면 모두 돌린다. `조서대조` 는 수식 조서를 실제로 풀어 엔진과
맞춰 보므로 오래 걸린다.

`손계산대조` 만 성격이 다르다. 나머지는 「엔진 == 조서」를 보므로 **둘이 같이 틀리면
통과한다** — 실제로 이표 지급일이 그랬다. 그래서 그 파일의 기대값은 엔진 결과가
아니라 계약에서 손으로 센 값이고, **엔진을 고쳤다고 갱신하면 안 된다.**

```
pip install formulas
python3 tests/손계산대조.py     # 손으로 센 기대값 == 엔진 (기대값 고정)
python3 tests/배선대조.py      # 조서 수식이 가정의 올바른 셀을 참조하는가
python3 tests/값조서대조.py     # 값 조서 == 엔진
python3 tests/리포트대조.py     # 부속 리포트(변동성·이자율) == 엔진
python3 tests/조서대조.py      # 수식 조서를 풀어서 == 엔진 (RCPS·실제 사례 포함)
python3 tests/조서대조.py 차바이오텍   # 이름으로 걸러 한 건만
python3 tests/주주간계약대조.py  # 주주간계약 조서 == 엔진
python3 tests/설정전수대조.py   # 설정을 하나씩 흔들어 배선 누락 확인
```

CB 회귀 기준선 — 이 값이 바뀌면 격자를 건드린 것이다. 기본 계약조건에
`carry=1`(경로가중치) · 노드 간격 1개월 · 무위험 `[(1,.0226),(3,.0240),(5,.0252)]` ·
위험 `[(1,.1409),(3,.1740),(5,.1905)]` 을 넣었을 때다.

```
주계약 37.5208 · 부채요소 73.1837 · 전체 112.9426 · 매도청구권 11.3910 · 전환권대가 38.2073
```

같은 조건에서 `carry=0`(상태확장)이면 전체 120.0576 · 매도청구권 13.5162 ·
전환권대가 40.3325 다. 어느 쪽인지 밝히지 않으면 기준선이 기준이 못 된다.

## 스트림릿 클라우드에 올리기

1. share.streamlit.io 에서 New app 을 누르고 이 저장소와 `app.py` 를 고른다
2. Deploy 를 누르면 몇 분 뒤 주소가 나온다

`requirements.txt` 를 저장소 루트에 두어야 필요한 패키지가 설치된다. `yfinance` 가
설치되지 않는 환경이라면 그 줄을 빼도 앱은 돌아간다 — 주가 자동 수집만 막히고 파일
붙여넣기는 그대로 된다. **코드를 고쳐 병합했으면 Rerun 이 아니라 Reboot app 을 눌러야
반영된다.**

## 적용범위

**주가를 관찰하거나 역산할 수 있는 단일 종류의 전환사채·신주인수권부사채·
상환전환우선주**를 이항격자로 재고 전환권·신주인수권·상환청구권·매도청구권·리픽싱을
분리해 조서를 만든다. **주주간계약**은 그 지분에 붙은 풋과 콜을 각각 잰다.

이 범위 밖은 넣지 않는다 — 종류주식 간 배분(OPM), 복수 투자라운드, 청산우선권,
IPO 확률을 확률변수로 두는 PWERM, 동반매도청구권·우선매수권은 별도의 모형이 할
일이다.

같은 문장이 조서 「가정」 시트 표지에도 미반영 조건과 함께 실린다.

## 한계

공통

- 리픽싱 기준주가를 조정일 종가로 단순화했다. 계약은 가중산술평균주가를 쓴다
- 조기상환 청구 시차(지급기일 60일 전~30일 전)를 반영하지 않는다
- 발행자가 가치극대화만 추구한다고 가정한다
- 행사일 당일 이표·배당은 지급하지 않는 것으로 본다 (만기만 지급). 표면이자율이
  0 이면 영향이 없다
- 리픽싱 근사법은 전환가격을 평균한다. 전환가치가 전환가격에 반비례하므로 가치를
  낮게 잡는 방향으로 치우친다 — 정확한 값은 상태확장이다
- **배당수익률은 연속 일정률 하나로만 받는다.** 배당락 일정을 타지 않으므로 특정일에
  몰린 배당은 근사다
- **기간에 따라 달라지는 배당률·이자율(step-up)을 받지 못한다.** 배당률 칸이
  하나뿐이라 단계적으로 오르는 계약은 첫 상환가능일 이후로 어긋난다
- 매도청구권의 **옵션차익혼합할인법은 TF 전용**이다. 노드의 지분·부채 분해 위에
  정의된 산식이라(한공회 4.4.3) GS 에서는 고를 수 없게 막았다

RCPS

- IPO 조항의 **예상 상장 시점은 가정**이다. 앱이 여러 시점과 「상장 없음」을 나란히
  내지만, 어느 가정을 조서에 썼는지는 밝혀야 한다
- 배당가능이익 한도(상법 345조)와 순자본비율 등 **상환재원 제약에 따른 실제 상환
  지연을 반영하지 않는다.** 계약상 상환일에 즉시 상환된다고 본다. 조서 표지에
  미반영 조건으로 적힌다
- 투자자 상환청구권이 없으면 앱이 경고하지만, **자본이라고 단정하지는 않는다.**
  발행자에게만 있는 상환권은 그 자체로 금융부채를 만들지 않으나(1032 AG25·AG26),
  배당의 지급재량·조건부 현금결제·전환 시 교부 주식 수를 함께 보아야 한다
- 상각표 시트는 평가기준일 배분액에서 출발해 **최초 인식 평가에만** 맞는다. 결산에는
  회계처리 탭의 「당기 이자비용」 표를 쓴다 — 발행 시점 조서의 유효이자율과 전기말
  장부금액을 넣어야 한다
- 종류주식 간 배분(OPM)은 범위 밖이다. 보통주 가격은 받거나 발행가로 역산한다

- **복합내재파생이 음수** — 발행자 상환권이 전환권보다 크면 부채 갈래 묶음이 음수 (대신증권 −9.0050)
- **배당가능이익·상환재원 제약 미반영** — 계약상 상환일에 즉시 상환된다고 본다
- **IPO 는 가정 비교이지 PWERM 이 아니다** — 상장 시점·공모가는 확률분포가 아니라 가정
- **자기신용위험 변동분(5.7.7) 분해 안 함** — 전체 FVPL 지정 후속측정에서 OCI 몫을 나누지 않는다
- **리픽싱 근사법(경로가중 등)은 근사** — E[1/K] ≠ 1/E[K]. 상태확장이 정확법
- **리픽싱 기준가 = 노드 주가 (VWAP 아님)** — 계약의 가중평균가 대신 노드 주가
- **사전통지기간 미반영** — 행사일 = 노드일
- **BW: 신주인수권증권 자체에 대한 콜 미지원** — 콜은 사채에 대한 권리로만 잰다
- **BW: 부분행사·다단계 행사가액 미지원** — 단일 행사·단일 행사가액

- **SHA: Drag/Tag/ROFR·다단계 strike 미지원** — 
- **역산이 목표를 정확히 못 맞힐 수 있다** — 격자 값의 계단 (0.19 등)
- **자동전환·상장 강제전환 RCPS 의 전환권이 음수** — 존속기간 만료 시 자동전환·상장 시 강제전환은 권리가 아니라 의무다. 주가가 낮으면 B2 < B1 이라 「전환권 = B2 − B1」 이 음수다 (분기전수·조합시험이 limit 로 허용)
- **강제전환 할인율 효과로 매도청구권이 음수** — TF·GS 는 지분을 무위험(전환확률 가중)으로 할인한다. 콜이 전환을 강제하면 부채가 지분으로 바뀌어 할인이 가벼워지고 전체 가치가 오를 수 있다 → 유무가치비교법 매도청구권 < 0. RCPS 발행자 상환권은 ca_debt=max(0,·) 로 막는다
- **잔여 주계약 ≤ 0 이면 상각표 없음** — 발행가 100 과 공정가치가 크게 다르면(Day-1 차이) 부채 분류의 잔여 주계약이 0 이하다. 유효이자율이 정의되지 않으므로 상각표를 만들지 않고 그 사실을 적는다 (4단계 F-05)
- **비분리형 BW 는 신주인수권 조기행사를 상태로 갖지 않는다** — 자식 노드의 매도청구는 신주인수권이 살아 있다고 보고 정해진다. 부모에서 투자자가 먼저 행사하면 그 콜은 사채만 비싸게 사는 셈이라 콜 있는 격자가 없는 격자보다 커질 수 있다 (매도청구권 < 0). 두 상태 격자로 고치는 것은 산식 변경이라 별도 승인 대상
