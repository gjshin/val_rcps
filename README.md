# 복합금융상품 평가 작업공간

CB · BW · RCPS · 주주간계약의 입력, 계산, 판단 보조와 Excel 조서를 한 흐름으로 처리합니다.
분리 판정 등 앱의 판정은 초안입니다. 평가자가 동의·수정과 근거를 적고, 기준서·실무사례 원문을 옆에서 확인합니다.

## 실행

```bash
pip install -r requirements.txt
python -m streamlit run app.py
```

화면 버전 **2026.09.30-workpaper.1**. 왼쪽 메뉴는 **평가 작업**, **여러 회차·변동 분석**입니다.
기존 평가파일과 계산부를 공유합니다. 몬테카를로는 사용하지 않습니다.

## 사용 순서

1. **입력·시장자료**: 계약조건·행사기간·주가·변동성·금리를 입력합니다. 변동성 산출, 주가 역산, 금리자료 도구도 이 화면에 있습니다.
2. **평가·분석 → 현재 입력으로 평가**: 결과·산술 검산·확인할 사항을 봅니다. 발행일 투자자 평가면 최초 인식 차이(모형값 / 거래가격 100 / 차이)와 처리 선택이 결과 맨 위에 나옵니다. 상세 계산 → **판단·근거**, 민감도, 계약조건 시나리오를 필요할 때 실행합니다.
3. **조서 출력 → 조서 생성 → Excel 조서만 저장**: 기본 값, 상세 계산 값, 상세 계산 수식 중 선택합니다. 회계처리·분개·상각표는 선택한 경우에만, 판단·근거 시트는 기본으로 포함됩니다.

검토자 지정·최종 확정 절차는 없습니다. 평가자 판단은 한 줄씩 적어 평가파일과 조서에 남깁니다. 입력을 바꾸면 현재 조건으로 다시 계산해야 조서를 생성할 수 있습니다.
입력은 세션에 반영되므로 종료 전 **평가파일 저장**으로 JSON을 보관하십시오. 출처와 별도 가정은 선택적으로 기록합니다.
추가 분석은 버튼을 누를 때 계산하며 기본 조서 생성은 주가 격자를 다시 평가하지 않습니다.

**계산 간격**: 월 / 2주(14일 기준) / 주(7일 기준). 주·2주는 기준일부터 만기까지 선택 일수에 가장 가까운 동일 간격으로 나누며 결과에 실제 평균 일수를 표시합니다.
기존 월 입력의 계산값은 유지합니다. 과거 `gap_m < 0.25` 입력은 엔진에서 0.25개월로 제한됐으므로 실제 주 간격과 같지 않습니다. 전기 비교 시 실제 구간 수도 확인하십시오.
격자는 1,200구간까지 지원합니다. 주 간격의 장기 수식 조서는 생성·재계산에 시간이 걸립니다.

## Excel 조서 구성

| 출력 | 시트 구성 |
|---|---|
| 기본 값 조서 | 평가요약, 계약조건, 시장자료, 평가방법, 금리곡선, 평가가정, 조서 정보(계산 정보·자료 출처·변동성 조회 조건·행사방식·확인할 사항) |
| 상세 계산 값·수식 조서 | 해설, 가정, 주가·전환가치·지분·부채·보유·금융상품가치·의사결정 격자, 결과, 이자율 산출내역(IR), 조서 정보. 상품·권리·계산방법에 따라 격자 시트가 달라짐. 리픽싱 조항이 없으면 전환가격·전환비율 격자(02·03)와 도달확률을 싣지 않음 |
| 상세 수식 조서 | 위 시트와 10 주계약가치·16 부채요소. 조서 정보에 「엑셀 수식으로 다시 계산한 값 = 앱 결과」 대조를 싣습니다. 앱 결과와 Excel 계산 결과의 차이를 표시. 트리 머리 17행과 행사금액 계산 과정은 「00 격자 공통」에서 한 번만 계산하고, 전환가격은 02a 이월 → 02b 정기 조정 → 02 전환가격 세 장으로 나눠 식을 짧게 했습니다 |
| 선택: 회계처리 초안 | 회계처리, 상각표. 현재 분류 가정에서 상각표가 적용되지 않으면 미산출 사유 표시 |
| 변동성 자료 적용 시 | 상세 조서에는 변동성 산출 시트(σ …), 그 밖에는 변동성원자료. 조회 조건은 조서 정보에 적음 |
| 기타 선택 입력 | 전기입력비교, 별도분석입력 |
| 판단·근거 (기본 포함) | 판단·근거: 분리 판정·평가방법·추가 검토 항목·최초 인식의 앱 판정(초안), 핵심 수치, 평가자 판단·근거, 근거 문단과 원문 발췌. 상세 조서는 분리 판단(수식 조서는 행사일별 10% 검토와 판정까지 수식)과 해설도 포함 |
| 보정 기록이 있을 때 | 보정기록: 보정일·보정 전후 주가·당시 주당가치·근거·이어 적용 식 |

검토기록·계약검토안·확정상태·계약반영표·독립검산대사 등 승인 절차용 시트는 출력하지 않습니다.
이전 파일의 해당 데이터는 불러오기·다시 저장하기 시 보존하지만 출력·승인의 필수 조건으로 사용하지 않습니다.
회계처리 시트 상단에는 입력 가정에 따른 초안이며 계약별 회계처리는 별도 검토한다는 안내를 표시합니다.
수식 조서는 평가와 같은 입력·격자를 사용합니다. Excel에서 파일을 열면 전체 재계산하도록 설정합니다.
8,192자를 넘는 수식은 해당 시트·셀을 알려 주고 생성을 중단합니다.
계산 점검(행사금액·배분 합계·분포 합 등)은 앱이 평가할 때 뒤에서 수행합니다. 이상이 있으면 조서를 만들지 않고 그 항목을 알려 줍니다 — 개발용 점검 시트(검산요약·99_모형검증·산술검산)는 조서에 싣지 않습니다.

## 수치 확인 및 추가 분석

- **확인할 사항**: 전환 시 주식수 증가율, 금리곡선 범위, 예시 곡선, 대상회사 주가와 입력 주가 차이, 저주가 리픽싱, 최초 인식 차이와 옛 입력 점검(상환청구권 부재·제3자 콜 한도 0%·리픽싱과 자본 분류·의무보유·BDT 변동성·행사금액표 등)을 한 줄씩 표시합니다.
- **판단·근거** (상세 계산): 계약상 권리표, 계약 조항 확인, 분리 판정(1109 B4.3.5(5) 10% 비교), 조기상환 행사 진단, 매도청구권 평가방법(여섯 단계·선택 근거), 풋·콜 우선순위, BDT 네 관문, 판정대로 배분, 추가 검토 항목. 판정 줄마다 **[원문]** 을 누르면 K-IFRS·일반기업회계기준·질의회신 문단과 한공회 실무사례(Series 11) 해당 쪽이 펼쳐집니다. 격자를 다시 도는 비교(콜 방법·우선순위·BDT)는 버튼을 눌렀을 때만 계산합니다.
- **최초 인식(Day 1)**: 「주가 역산」을 발행일 평가에서 적용하면 보정 기록을 남기고, 다음 분기에 「보정 이어 적용」으로 새 주가 = 보정 주가 × (이번 주당가치 ÷ 보정일 주당가치)를 넣습니다. 보정하지 않은 차이는 「이연(기본)」 또는 근거를 적은 「당기손익」으로 분개하며(1109 B5.1.2A), 원인 점검 3항목이 판단·근거에 생깁니다.
- **변동성**: 「입력·시장자료 → 주가·변동성·금리 자료 → 변동성 산출」. Yahoo 수정주가 또는 종가 파일을 사용합니다. 엄격한 검사가 기본이며 필요하면 「못 받은 종목 빼고 계산」·「빈 날짜 빼고 계산」을 선택합니다. 제외 종목·일자·사유, 관측치 부족과 선택한 옵션을 조서에 남깁니다. 0·음수·중복·미래 날짜는 허용하지 않습니다. 상장사 원자료도 조서에 포함합니다.
- **부분상환·지급시차·누적배당**: 「평가·분석 → 계약조건 시나리오」. 예정 비율·기지급배당·지급일 할인 등을 명시한 조건부 계산이며 기본값에 자동 합산하지 않습니다.
- **여러 회차·변동 분석**: 독립 회차 합산과 전기 대비 변동 대사를 유지합니다. 상호 희석·청산순위의 공동 평가는 포함하지 않습니다.

## 명령 도구

`tools/run_case.py`가 단일 구현입니다. `tools/run_valuation.py`는 이전 명령을 같은 구현으로 연결하는 호환 입구입니다.
고객 자료·평가파일·조서는 저장소 밖에 보관하십시오.

```bash
python tools/run_case.py /outside-repo/case.json --inspect
python tools/run_case.py /outside-repo/case.json --out /outside-repo/value.zip
python tools/run_case.py /outside-repo/case.json --out /outside-repo/detail.zip --detail --accounting
python tools/run_case.py /outside-repo/case.json --out /outside-repo/formula.zip --formula --check-formulas
python tools/run_case.py /outside-repo/case.json --set S0=10000 --set grid_days=7 --sens /outside-repo/scenarios.json --out /outside-repo/scenarios.zip
python tools/run_case.py /outside-repo/case.json --vol /outside-repo/vol.json --vol-out /outside-repo/vol.xlsx --out /outside-repo/value.zip
python tools/run_engagement.py /outside-repo/engagement.json --out /outside-repo/engagement.zip
```

`--set`은 반복 가능하며 행사일은 `p_s_date=2035-04-09`처럼 지정할 수 있습니다.
민감도 파일은 `[ {"label":"주가 +10%", "set":{"S0":11000}} ]` 형식입니다.
`--check-formulas`는 **출력한 전체 격자**를 LibreOffice로 재계산하여 앱 값과 대사합니다. LibreOffice 설치가 필요하며 `VALUATION_SOFFICE`로 실행 경로를 지정할 수 있습니다.
조서의 생성과 재계산 검사는 구분합니다. Microsoft Excel에서의 직접 열기 검사는 해당 실행환경에서 별도로 수행해야 합니다.

## 기존 계산부의 한계

아래 목록은 기존 엔진 및 상세 기능의 적용 범위입니다. 별도 계약조건 분석은 입력한 일정에 한정되며 이 한계를 모두 해소한 모형이 아닙니다.

- **복합내재파생이 음수**: 발행자 상환권이 전환권보다 크면 부채 갈래 묶음이 음수 (대신증권 −9.0050)
- **의무보유 물량 = 콜 대상비율**: 의무보유 물량을 k_w 와 같다고 본다. 「콜 한도 30%인데 의무보유는 20%」처럼 두 물량이 다른 계약과 「30% → 20% → 10% 단계적 해제」처럼 물량이 시간에 따라 갈리는 계약은 담지 못한다 — 사채를 물량별로 쪼개 격자를 따로 풀고 조서에도 트리를 벌수만큼 실어야 한다. 기간(k_lock)과 제한 권리(k_lock_put)는 표현된다
- **부분 매도청구는 뿌리에서 비율로만 반영**: 뿌리값에 k_w 를 곱한다. 행사금액이 물량에 비례하고 한도가 전체 기간에 하나뿐이면 발행자는 이득이 나는 순간 한도를 다 쓰는 것이 언제나 최선이므로 이 처리는 근사가 아니라 정확하다. 담지 못하는 것은 기간별 세부한도가 붙은 계약(「전체 30%인데 매년 10%씩만」)이다 — 남은 한도가 상태변수가 되어 상태확장이 필요하다
- **배당가능이익·상환재원 제약 미반영**: 계약상 상환일에 즉시 상환된다고 본다
- **전환 희석 미반영**: 기초주가를 받은 그대로 쓴다. 전환으로 늘어나는 주식수와 사라지는 부채를 주가에 되먹이지 않는다 — 희석 반영 주당가치를 밖에서 산정해 넣어야 한다. 보통주식수·전환 시 증가 주식수를 넣으면 비율이 10% 를 넘을 때 경고한다
- **회사 행위로 조정되는 전환가액(희석방지 조항) 미반영**: 저가 신주발행·무상증자·합병처럼 회사의 결정으로 일어나는 조정은 주가 격자로 표현할 수 없다. 주가만 보는 리픽싱(정기 · 언제든지)과 IPO 공모가 연동만 반영한다
- **IPO 는 가정 비교이지 PWERM 이 아니다**: 상장 시점·공모가는 확률분포가 아니라 가정
- **자기신용위험 변동분(5.7.7) 분해 안 함**: 전체 FVPL 지정 후속측정에서 OCI 몫을 나누지 않는다
- **리픽싱 근사법(경로가중 등)은 근사**: E[1/K] ≠ 1/E[K]. 전환가격 경로를 모두 들고 가는 정확법(상태확장)은 조서로 옮길 수 없어 없앴다. 예전 파일의 상태확장 설정은 경로가중으로 연다
- **리픽싱 기준가 = 노드 주가 (VWAP 아님)**: 계약의 가중평균가 대신 노드 주가
- **사전통지기간 미반영**: 행사일 = 노드일
- **BW: 신주인수권증권 자체에 대한 콜 미지원**: 콜은 사채에 대한 권리로만 잰다
- **BW: 부분행사·다단계 행사가액 미지원**: 단일 행사·단일 행사가액
- **SHA: 상대방 신용은 할인율로만**: 부도 손실률·회수율 구조 없음
- **SHA: Drag/Tag/ROFR·다단계 strike 미지원**:
- **역산이 목표를 정확히 못 맞힐 수 있다**: 격자 값의 계단 (0.19 등)
- **자동전환·상장 강제전환 RCPS 의 전환권이 음수**: 존속기간 만료 시 자동전환·상장 시 강제전환은 권리가 아니라 의무다. 주가가 낮으면 B2 < B1 이라 「전환권 = B2 − B1」 이 음수다 (분기전수·조합시험이 limit 로 허용)
- **강제전환 할인율 효과로 매도청구권이 음수**: TF·GS 는 지분을 무위험(전환확률 가중)으로 할인한다. 콜이 전환을 강제하면 부채가 지분으로 바뀌어 할인이 가벼워지고 전체 가치가 오를 수 있다 → 유무가치비교법 매도청구권 < 0. RCPS 발행자 상환권은 ca_debt=max(0,·) 로 막는다
- **잔여 주계약 ≤ 0 이면 상각표 없음**: 발행가 100 과 공정가치가 크게 다르면(Day-1 차이) 부채 분류의 잔여 주계약이 0 이하다. 유효이자율이 정의되지 않으므로 상각표를 만들지 않고 그 사실을 적는다 (4단계 F-05)
- **주가 basis 검증은 내부 신호뿐 — 분할 이력은 참고**: 분할·병합·무상증자 여부는 원주가 대 수정주가의 배수와 전환가 계열의 정합성으로만 판정한다. 야후의 분할 이력은 한국 종목 커버리지가 고르지 않고 특히 무상증자를 split 으로 기록하지 않는 경우가 많아 근거로 쓰지 않는다 — 「기록 없음」이 「사건 없음」이 아니다. 조정사건이 의심되면 공시로 확인해야 한다
- **주가와 금리를 함께 흔드는 결합격자 미지원**: 주가 이항격자와 BDT 금리격자를 곱한 2요인 격자를 만들지 않는다. 전환권이 파생상품부채인 CB 는 주계약과 내재파생 전체를 하나의 복합내재파생으로 재므로 조기상환권을 따로 잴 이유가 없고, 전환권이 자본이라 조기상환권만 부채요소에 남는 경우에만 BDT 를 쓴다. 두 위험의 상관을 반영해야 하는 계약은 고도화 대상이다
- **비분리형 BW 는 신주인수권 조기행사를 상태로 갖지 않는다**: 자식 노드의 매도청구는 신주인수권이 살아 있다고 보고 정해진다. 부모에서 투자자가 먼저 행사하면 그 콜은 사채만 비싸게 사는 셈이라 콜 있는 격자가 없는 격자보다 커질 수 있다 (매도청구권 < 0). 두 상태 격자로 고치는 것은 산식 변경이라 별도 승인 대상
